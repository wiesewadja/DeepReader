## 设计意图 (why)

LangGraph S2 Analytical 节点跑 ReAct 工具循环——**LLM 自由选工具、自定循环次数**。

**问题**：
- 用户问"这本书讲什么"（检视阅读）→ LLM 不该跑 5 次工具循环，**2 次就该停**
- 用户问"对比两本书"（主题阅读）→ LLM **必须**允许 6+ 次跨书检索
- LLM 自由度高 → **意图无关的工具**会被误调（"讲什么" 不该调 `write_note` 写笔记）

**IntentRouter 解决**：
- **0 LLM 调用**（纯正则匹配，< 1ms）
- **动态收紧 allowedTools**——S2 节点的 LangChain 工具集过滤到意图相关
- **动态 maxIterations**——ReAct 循环提前结束
- **注入 `<system_note>`**——告诉 LLM"你只被允许用 X 工具"

**5 条规则对应 Adler《如何阅读一本书》的 4 个层次**：

| 规则 | 对应阅读层次 | 工具数 | 迭代上限 |
|---|---|---|---|
| `macro_overview` | 检视阅读（基础） | 1 | 2 |
| `locate_chapter` | 分析阅读-定位 | 3 | 3 |
| `concept_inquiry` | 分析阅读-概念探究 | 3 | 3 |
| `action_output` | 动作输出（写笔记/出图） | 4 | 3 |
| `syntopical` | 主题阅读（最高） | 3 | 6 |
| `fallback` | 兜底（微观检索） | 2 | 4 |

## system_note 注入 (system-note)
### 兜底（fallback）

```json
{
  "fallback": {
    "intent": "分析阅读-微观检索",
    "tools": ["search_markdown_text", "read_markdown_section"],
    "maxIterations": 4,
    "comment": "兜底场景，给予足够空间"
  }
}
```

**为什么**：
- 不匹配任何规则（用户问题特别冷门）→ 不能直接 fallback 到"什么都不允许"
- 给搜索 + 章节阅读两个最基本工具，**用户至少能拿到原文片段**
- 迭代上限 4（中等）

### tool_aliases

```json
"tool_aliases": {
  "outline": "get_document_outline",
  "section": "read_markdown_section",
  "search": "search_markdown_text"
}
```

**用途**：规则配置中可以用短名 `outline` → 实际加载时映射为 `get_document_outline`。
**目前**：`intent-rules.json` 里**没**用短名（直接写完整名）—— 保留扩展。

**位置**：`src/agent/router/intent-router.ts:42-105`

### 输入

```typescript
analyze(userInput: string | string[], traceCtx?: ITraceContext): IntentResult
```

- `userInput`：单字符串或**多段并集**（`rawQuery` + `rewrittenQuery`）
- `traceCtx`：可选追踪上下文（LangSmith 集成用）

### 算法 5 步

```typescript
analyze(userInput, traceCtx) {
  // 1. 创建追踪 span
  const span = traceCtx?.withSpan('intent-routing', { ... });

  // 2. 对每段输入遍历规则，匹配意图（取并集）
  const detectedIntents = [];
  const allowedTools = new Set();
  let maxIterations = null;

  for (const text of inputs) {             // 遍历每段输入
    for (const { rule, pattern } of compiledRules) {
      if (pattern.test(text)) {             // 正则匹配
        detectedIntents.push(rule.intent);  // 累加意图
        rule.tools.forEach(t => allowedTools.add(t));  // 累加工具
        // 取所有匹配规则中**最大**的 maxIterations
        maxIterations = max(maxIterations, rule.maxIterations || 4);
      }
    }
  }

  // 3. 兜底
  if (detectedIntents.length === 0) {
    detectedIntents.push(fallbackIntent);
    fallbackTools.forEach(t => allowedTools.add(t));
    maxIterations = fallbackMaxIterations;
  }

  // 4. 构建 system note
  const systemNote = buildSystemNote(detectedIntents, allowedTools);

  // 5. 结束追踪 + 返回
  span?.end({ detectedIntents, allowedTools, maxIterations, duration });
  return { allowedTools, systemNote, detectedIntents, maxIterations };
}
```
## 已知限制 (limits)
### 关键设计

- **多输入并集**：`rawQuery` + `rewrittenQuery` 都跑一遍，**累加**意图和工具（不互斥）
- **取最大迭代上限**：用户多意图时按"最复杂意图"算上限（保守）
- **正则预编译**：`constructor` 里就把所有 `pattern` 编译成 `RegExp`，避免每次 `analyze` 重编译
- **正则容错**：`new RegExp` 抛错时回退到 `/$^/`（永不匹配）—— **不让一个坏规则拖垮整个 router**

---
**位置**：`intent-router.ts:110-117`

### 输出格式

```html
<system_note>
【Router 强制路由】
系统已判定用户意图包含：检视阅读、分析阅读-概念探究。
你当前仅被允许使用以下工具：[get_document_outline, search_markdown_text, read_markdown_section]。
严禁使用其他未列出的工具。
</system_note>
```

### 注入点

`Inspectional (含 S0 Router) 节点` → 拼到 system prompt 末尾 → S2 Analytical 节点收到 LLM 时已经看到。

**效果**：
- LLM 在 system prompt 里被告知"你只被允许 X 工具"
- 即使 LangChain 工具集过滤了，**LLM 也有"认知层面"的遵守**
- **双重保险**：工具集过滤（机制层） + system_note（认知层）

### 安全考虑

**注意**：如果 LangChain 工具集过滤**漏了**一个工具，LLM 仍能调——system_note 只是**劝阻**。**真正的安全边界是工具集过滤**（在 `buildGraphConfigurable` 里过滤 LangChain `tools` 参数）。

## 与状态机的集成 (integration)

### 调用链

```
用户问问题
  └─→ Inspectional (含 S0 Router) 节点
        ├─→ IntentRouter.analyze(rawQuery, rewrittenQuery, traceCtx)
        │     └─→ IntentResult { allowedTools, systemNote, maxIterations }
        │
        ├─→ 写 state.allowedTools + state.systemNote
        │
        └─→ S1 Inspectional / S2 Analytical 节点读取
              ├─ LangChain 工具集过滤：tools = filter(state.allowedTools)
              └─ system prompt 末尾追加 state.systemNote
```

### 关键代码

```typescript
// Inspectional (含 S0) 节点内部：IntentRouter 调用伪代码
const intentResult = intentRouter.analyze([
  state.rewrittenQuery,
  ctx?.rawUserQuery,
], traceCtx);

return {
  detectedIntent: intentResult.detectedIntents.join('+'),
  allowedTools: intentResult.allowedTools,
  // ... 写入 LangGraph state
};
```

### 边界

**IntentRouter 是"建议层"，不是"强制层"**：

- 工具集过滤**机制层**在 `buildGraphConfigurable` 里真正生效
- maxIterations **在 ReAct 循环**的 `maxSteps` 参数里生效
- system_note 只是**劝阻** LLM 调未列工具

**三层防御**：工具集过滤 + maxIterations + system_note 互相补强。

- **正则匹配是字符级**——"总结一下" 命中但 "我想总结一下阅读体验" 也命中
- **多意图冲突**——"对比两本书，写个笔记" 既命中 syntopical 又命中 action_output，**两者工具都允许**（可能 LLM 滥用）
- **priority 字段保留但未用** —— `IntentRule.priority` 在类型里有，**但代码里没读取**
- **tool_aliases 字段保留但未用** —— 配置里定义了映射，**实际规则直接写完整名**
- **不支持 LLM 重新分类** —— IntentRouter 是"硬规则"，无法让 LLM override（"其实这个不是总结，是 X"）
- **正则性能 O(n×m)** —— 5 条规则 × 多段输入（2 段） = 10 次正则匹配，**不是瓶颈**但用户输入特别长时可能慢
- **fallback 工具集太窄** —— 兜底只给搜索 + 章节，**没法画图 / 写笔记**（用户问"画个思维导图"恰好没匹配任何规则时被卡住）
