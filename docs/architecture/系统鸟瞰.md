## 顶层架构（layers）

```
┌──────────────────────────────────────────────────────────────────┐
│  L1  入口层：Obsidian Plugin 注册 / Commands / Protocol Handlers  │
│      └─ src/main.ts: DeepReaderPlugin                            │
├──────────────────────────────────────────────────────────────────┤
│  L2  UI 层                                                       │
│      ├─ Sidebar  (主聊天 + 阅读控制)   src/views/sidebar/*       │
│      ├─ Library  (书库)                src/views/library-view    │
│      ├─ Z-Library 搜索                 src/views/zlibrary-...    │
│      └─ ReadingMode Service (高亮/选区) src/views/sidebar-view   │
├──────────────────────────────────────────────────────────────────┤
│  L3  FrontendAgent（统一入口）                                   │
│      └─ src/agent/index.ts: FrontendAgent                        │
│         - chat() / runGraphEngine() / resumeGraphExecution()     │
│         - 持有 LLMClient / ContextLoader / MemoryStore / Router  │
├──────────────────────────────────────────────────────────────────┤
│  L4  Cognitive Engine（LangGraph 状态机）                        │
│      └─ src/agent/graph/index.ts: cognitiveEngine                │
│         routeFromStart → Inspectional (含 S0 Router) → S2-Pre → │
│         S2/S3 → S4 Format                                       │
│         旁支: S-Advisor（无书模式）/ S-Visualizer（图表/Hermes）  │
├──────────────────────────────────────────────────────────────────┤
│  L5  基础服务（Foundation Services）                             │
│      ├─ PageIndex    PDF/EPUB 解析 + 树形索引    src/pageindex/* │
│      ├─ Tools        LangChain 工具集            src/agent/tools │
│      ├─ Skills       策划知识 / Markdown          src/agent/skills│
│      ├─ Session      会话持久化                  src/agent/session│
│      ├─ WeRead       微信读书                    src/weread/*     │
│      ├─ Hermes MCP   图表生成                    src/services/*   │
│      └─ TTS / ASR    语音                        src/services/*   │
└──────────────────────────────────────────────────────────────────┘
```

**层间依赖方向**：上层依赖下层，禁止反向引用（参见 `scripts/arch-guard.mjs` 强制）。
每层都可以独立 mock 注入，便于测试和替换。

## 执行链：用户问问题后发生什么（flow）

```
DeepReaderPlugin (main.ts)
  └─→ SidebarView
        └─→ AgentChatController.chat()
              └─→ FrontendAgent.runGraphEngine()
                    └─→ executeWithStream()
                          └─→ cognitiveEngine.stream()
                                └─→ 流式节点处理
                                      └─→ processStream()
                                            └─→ 回调到 UI
```

**关键点**：

- `FrontendAgent` 用**单例 + 延迟初始化**，首次聊天时构造（`getFrontendAgent()`）。
- **双 LLM 配置**：main + fast（便宜的 fast 做 router(S0) + inspectional(S1)）。
- **LangSmith tracing** 可选注入到 `callbacks`。
- `runGraphEngine` 与 `resumeGraphExecution` 共享 `executeWithStream`（HITL 续跑）。
- `cancelToken` / `abortSignal` 全链路传递——取消即停所有下游。

**配置打包**（`buildGraphConfigurable`）：

```typescript
{
  thread_id:        "thread-{bookId}-{ts}",
  fastModel:        ChatOpenAI,   // S0 / S1 / 提议抽取
  mainModel:        ChatOpenAI,   // S2 / S4 主对话
  sharedContext:    SharedContext,// 记忆 + 画像 + 历史摘要 + 工具上下文
  toolContext:      ToolContext,  // 工具执行环境（vault / plugin / book）
  callbacks:        EngineCallbacks, // onContent / onProgress / onError
  enableHumanReview: boolean,     // HITL 开关
  _langsmithTracer: Tracer | null,// 可选追踪
}
```

`config.configurable` 是节点读取外部依赖的唯一通道——便于 mock 与单元测试。

## 状态机（state-machine）

```
START ──┬─(proactive)──► INSPECTIONAL ──► ... ──► FORMATTER ──► END
        │
        ├─(无书 + WeRead)──► ADVISOR (ReAct with weread_*)
        └─(有书)──► INSPECTIONAL (含 S0+S1，一次 LLM 调用)
                        ├─...(depth=0 casual / socratic)──► FORMATTER
                        ├─(depth=3 syntopical)──► SYNTOPICAL
                        ├─(depth=1 + 图)──► VISUALIZER → FORMATTER
                        └─(depth=1 无图/depth=2)──► PRE_SEARCH
                                          │
                          ┌───────────────┴──────────────┐
                          │ earlyStopContent    → FORMATTER
                          │ correctionDetected  → ANALYTICAL
                          │ verifiedFullBookHits→ ANALYTICAL
                          │ 默认               → ANALYTICAL
                                          │
                ANALYTICAL (S2) ──┬─(有图)──► VISUALIZER ─┐
                                   └─(无图)──► FORMATTER   │
                                                              │
                SYNTOPICAL (S3) ──────────────────────────────┤
                                                              │
                ADVISOR ─────────────────────────────────────┤
                                                              ▼
                                                        FORMATTER ──► END
```

**6 节点 + 4 条件边**（S0 Router 已合并到 Inspectional）

### 节点一览

| 节点 | 文件 | 职责 | 兜底策略 |
|---|---|---|---|
| S1 Inspectional (含 S0 Router) | `nodes/inspectional.ts` | 统一路由 + 检视阅读：depth 分类 / 查询重写 / 范围选择 / 结构分析 | `safeNode` 降级到 depth=2 空 scope |
| S2-Pre | `nodes/analytical-pre-search.ts` | 预检索 + 早停判断 | `safeNode` 透传 scope |
| S2 Analytical | `nodes/analytical.ts` | 跑 ReAct / PlanExecute 工具循环 | `safeNode` 输出空 analysis |
| S3 Syntopical | `nodes/syntopical.ts` | 跨书 RAG 融合 | `safeNode` 输出空 analysis |
| S-Advisor | `nodes/advisor.ts` | 无书模式，调用 WeRead 工具 | `safeNode` 输出空 analysis |
| S-Visualizer | `nodes/visualizer.ts` | 调 Hermes 生成图表/信息图 | 失败时 formatter 兜底 |
| S4 Formatter | `nodes/formatter.ts` | 最终答案格式化 + wiki 链接生成 | `safeNode` 返回 `analysisResult` 原样 |

### 条件边（`edges.ts`）

| 函数 | 决定 |
|---|---|
| `routeFromStart` | proactive 直接走 S1，无书+WeRead→ADVISOR，有书→INSPECTIONAL |
| `routeAfterInspectional` | socratic/proactive → done / depth=1+图 → visualizer / depth=1 无图 → done / depth=2 → S2-Pre |
| `routeAfterInspectional` | socratic/proactive → done / depth=1+图 → visualizer / depth=2 → S2-Pre |
| `routeAfterPreSearch` | correctionDetected → analytical / 早停 → formatter / 默认 → analytical |
| `routeAfterAnalysis` | 有图 → visualizer / 否则 → formatter |

## 状态字段（state）

LangGraph `Annotation.Root` 定义；`messages` 用 `messagesStateReducer`（append），其余 last-value 语义。

| 分组 | 字段 | 写入者 | 说明 |
|---|---|---|---|
| 消息 | `messages` | 全节点 | BaseMessage[]（append） |
| 路由 | `depth`, `rewrittenQuery`, `allowedTools` | S1 Inspectional（含 S0 Router） | 分类结果 |
| S1 | `tocSummary`, `scopeNodeIds`, `betterQuestion`, `structuralAnalysis`, `suggestedKeywords` | Inspectional | 锁定章节范围 |
| S2-Pre | `preSearchBlock`, `earlyStopContent`, `validatedScopeNodeIds`, `nodeFileMap`, `prevSearchedBlockIds` | PreSearch | 预检索 + 早停 |
| S2 | `analysisResult`, `toolResultsSnapshot` | Analytical | 主体输出 |
| S4 | `formattedOutput` | Formatter | 最终答案 |
| 运行时 | `bookId`, `pdfName`, `mode`, `wereadAvailable`, `crossBookMode` | 启动 / 节点 | 上下文 |
| 纠错 | `correctionDetected`, `verifiedFullBookHits` | S1 Inspectional / S2-Pre | 触发 S2 重启 |
| 主动 | `proactiveTrigger`, `highlightContext` | Proactive Engine | 苏格拉底引导 |
| 错误 | `nodeErrors` | 任意节点 | `NodeError { message, recoverable, fallbackAction }` |

## 索引流水线（pipeline）

### PDF 路径

```
pdf-parse (text + outline)
  └─→ core/toc.ts          识别 TOC 页（含 heuristic 兜底）
        └─→ core/tree.ts   构建层级树
              └─→ pageindex.ts  生成 JSON + LLM 摘要
                    └─→ exporters/  →  Obsidian notes
```

### EPUB 路径

```
epub.ts (OPF/HTML 解析)
  └─→ splitLargeEpubPages  按 token 切分超大章节
        └─→ epub-to-obsidian.ts
              ├─ classifyTitle      标题分类（part/chapter/section/special/other）
              ├─ calculateLevels    层级计算
              └─ buildEpubTree      树构建
                    └─→ Obsidian notes
```

### 关键设计

- **nodeId** 用 4 位数字（`0001`, `0002`），便于序列化与排序。
- **block_id** 在 Markdown 正文用 `^xxx` 锚点反向追踪，工具结果自动抽取。
- **目录迁移**：`migrateBookIndexes` 一次性把 path-hash 迁到 content-hash（幂等）。
- **路径隔离**：`setActivePluginId(this.manifest.id)` 区分 dev / daily 两个构建。
- **配置文件落点**：`.obsidian/plugins/deepreader/pageindex/`，不在 Vault 主目录。

### 解析质量兜底

- PDF 扫描页：用 MinerU API（`src/services/mineru-api.ts`）做 OCR 补盲
- EPUB 异常格式：`fixAbnormalAsterisks` 修复分散单字符加粗
- 大章节切分：超过 token 阈值的章节按 `EPUB_SPLIT_PATTERN` 切分

## 关键技术点：设计巧思（tricks）

1. **HITL 中断 + 恢复**：`activeThreadId` 缓存 + `Command({ resume })` + `MemorySaver` checkpointer
2. **5 层 fallback**：`safeNode(NODE, fn, fallbackFn)` 包装保证单节点崩溃不会卡死整张图
3. **L5 负向声明核验**：`routeAfterPreSearch` 检测 `verifiedFullBookHits` 时强制重启 S2，修复 S2-Pre 早停路径的"未出现"幻觉
4. **correct 路径兜底**：`correctionDetected` 跳过早停 + 重新纳入当前章节
5. **统一错误模型**：`NodeError { message, recoverable, fallbackAction }` + `NODE_ERROR_HINTS` 友好提示
6. **Block ID 双向追溯**：工具结果中提取 `block_ids` → S2→S4 自我验证（`utils/claim-verifier.ts`）
7. **工具结果压缩**：单条 `compressToolResult` 截断 + `compressMessagesForLLM` 保留最近 N 条全量
8. **Loop 检测**：ReAct 的 `loop_detected` finishReason + 重复查询检测
9. **记忆双层**：MEMORY.md 长期（带主动压缩）+ JSONL 会话历史（按需加载）
10. **AbortSignal 全链路**：用户取消即停所有下游节点 + 工具调用

## 风险与待办（issues）

> 以下基于 codegraph 静态扫描结论，未做运行验证，标 [INFERENCE]。

- **测试覆盖薄弱 [INFERENCE]**：核心图节点（`runGraphEngine` / `executeWithStream` / `safeNode` / `routeAfterPreSearch`）**无单测**。唯一有覆盖的是 PageIndex parser 层。
- **UI ↔ Agent 边界 0 测试 [INFERENCE]**：`AgentChatController` 是 UI 和 Agent 唯一桥梁，但无单测。
- **死代码风险 [INFERENCE]**：`humanized-types.ts` 的 `TOOL_TO_ACTION` 注释里出现 `search_book` / `read_book_section`，但实际工具名是 `search_markdown_text` / `read_markdown_section`——可能是旧 API 残留。
- **`hasDiagramIntent` 永远返回 `false` [INFERENCE]**：图表生成已迁到 Hermes，但保留路由分支——可考虑清理。
- **配置双层架构复杂度 [INFERENCE]**：`providers` + `roles` 两层对用户暴露略多，是否需要更简单的"主备"切换 UI 可讨论。
- **图片/截图类输出 [INFERENCE]**：visualizerNode 已有但只在 depth=1 + 图表意图时触发，formatter 阶段未涉及——如需任意深度图表化，需补全。
