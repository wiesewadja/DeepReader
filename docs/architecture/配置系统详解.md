## 为什么需要两层架构 (why-two-layers)

DeepReader 同时支持 7 个 LLM 服务商，每个服务商的 API Key / baseUrl 通常只有一个，**但内部却有 8 种用途**（对话 / 路由 / 索引 / 命题 / 嵌入 / 重排 / 语音 / 图片）。

如果让用户给每种用途单独填一个 API Key，会出现 8 个 Key 的"配置灾难"。如果所有用途共用一个 Key + 一个模型，**"快+便宜的小模型做路由"**这种优化就做不了。

**两层架构解法**：

```
AIProviderAccount（账号层）    AIRoleConfig（角色层）
   1 个 API Key                     8 个用途
   1 个 baseUrl                     每个指向某个账号 + 1 个模型
   1 个服务商（minimax/xiaomi/...）
```

- 账号层 1-3 个：典型 1 个，最多 2 个（主 + 副 Provider）
- 角色层 8 个：必填 3 个（chat/router/pageindex），可选 5 个（proposition/embedding/reranker/tts/imagegen）

用户视角：填 1 套账号 + 8 个用途下拉选模型，**共 9 个 UI 字段**（API Key × 1-3 + 模型 × 8），不是 24 个。

## 数据模型 (model)

### 第一层：AIProviderAccount（`src/config/ai-roles.ts:24-30`）

```typescript
interface AIProviderAccount {
  apiKey: string;          // 必填
  baseUrl?: string;        // 自定义服务商必填，固定服务商用默认值
  name?: string;           // 显示名称（自定义服务商用）
  fallbackApiKey?: string; // 主 Provider（仅 xiaomi）的备用 Key，Token Plan 欠费时切换
  fallbackBaseUrl?: string;
}
```

**关键设计**：
- `fallbackApiKey` 仅 xiaomi 支持——小米 MIMO 的 Token Plan 模式，**欠费时自动切换到 pay-as-you-go 模式**，用户体验无感
- 自定义服务商必须填 `baseUrl`——固定服务商的 URL 硬编码在 `providers.ts` 里

### 第二层：AIRoleConfig（`src/config/ai-roles.ts:33-39`）

```typescript
interface AIRoleConfig {
  provider: string;            // ProviderType 或自定义服务商 ID
  model: string;               // 空字符串 = 使用服务商默认模型
  baseUrlOverride?: string;    // 覆盖该角色的 baseUrl（高级用户用）
  embeddingBatchSize?: number; // embedding 专用，默认 32
  disableThinking?: boolean;   // undefined=自动, true=强制禁, false=不禁
}
```

**关键设计**：
- `provider: string` 而非 `ProviderType`——**允许引用自定义服务商**
- `model: ''` 含义是"用该 Provider 的默认模型"——**典型用法**是 OpenAI 用户不指定具体模型
- `baseUrlOverride` 极少用——只有代理或测试场景
- `disableThinking` 适配 thinking 能力（如 DeepSeek R1）——**自动检测**按模型名匹配

### 8 角色配置（`src/config/ai-roles.ts:42-51`）

```typescript
interface AIRoles {
  chat:        AIRoleConfig;            // 必填
  router:      AIRoleConfig;            // 必填
  pageindex:   AIRoleConfig;            // 必填
  proposition: AIRoleConfig | null;    // null = 禁用命题卡片
  embedding:   AIRoleConfig | null;    // null = 禁用嵌入，降级 BM25
  reranker:    AIRoleConfig | null;    // null = 禁用重排
  tts:         AIRoleConfig | null;    // null = 禁用语音
  imagegen:    AIRoleConfig | null;    // null = 禁用图片
}
```

**3 必填 + 5 可选**——8 个角色里只有 3 个不能 null。

## 7 服务商 × 能力矩阵 (providers)

> 数据源：`src/config/providers.ts:PROVIDER_CONFIGS` 实时计算

| Provider | chat | embedding | reranker | tts | imagegen | 默认 baseUrl |
|---|---|---|---|---|---|---|
| `minimax` | ✓ | ✓ | — | — | ✓ | (内置) |
| `deepseek` | ✓ | — | — | — | — | (内置) |
| `kimi` | ✓ | — | — | — | — | (内置) |
| `siliconflow` | ✓ | ✓ | ✓ | — | — | (内置) |
| `openai` | ✓ | ✓ | ✓ | — | — | (内置) |
| `xiaomi` | ✓ | — | — | ✓ | — | (内置) |
| `sensenova` | ✓ | — | — | — | ✓ | (内置) |
| `custom` | ✓ | ✓ | ✓ | — | — | 用户填 |

**约束**：`src/config/types.ts:15` 的 `RequiredCapability` 类型 = 8 个角色能映射到的能力集合。**`ROLE_CAPABILITY` 不可改**——它是 8 个角色每个的"最低要求"。

**为什么 Provider 数量是 7+1？**：
- 7 固定服务商：与 LLM 厂商合作 / 通用 OpenAI 协议
- `custom` 兜底：用户填 baseUrl + apiKey + 模型名——支持任何 OpenAI 兼容 API

## 8 角色 × 必填/可选 (roles)

| 角色 | 必填? | 消费方 | null 行为 | 备注 |
|---|---|---|---|---|
| `chat` | ✓ | S2 Analytical / S4 Formatter 主对话 | 不可 null | mainModel 来源 |
| `router` | ✓ | S1 Inspectional（含原 S0 Router）意图分类 | 不可 null | fastModel 来源（便宜） |
| `pageindex` | ✓ | PageIndex LLM 摘要 | 不可 null | 长上下文友好模型 |
| `proposition` | 可选 | 命题卡片提取（已禁用） | null = 禁用 | L5 L5 复核等不依赖 |
| `embedding` | 可选 | L0/L1/L2 向量化、查询嵌入 | null = 降级纯 BM25 | 影响**所有**搜索质量 |
| `reranker` | 可选 | searchBookV2 Stage 7 | null = 跳过重排 | 不致命但搜索质量下降 |
| `tts` | 可选 | 语音合成（小米 v2.5-tts） | null = 禁用语音 | 仅影响 TTS 入口 |
| `imagegen` | 可选 | Proactive 引导 / Visualizer | null = 禁用 | 极少数入口用 |

**设计意图**：`chat` / `router` / `pageindex` 是**核心 LLM 决策链**——必须配。`embedding` / `reranker` 是**搜索增强**——有就更好，没有也能跑（降级）。

**注意**：`router` 故意单独拆——**让用户能用便宜的小模型做意图分类**（典型选 `mimo-v2.5` 而非 `mimo-v2.5-pro`），节约 token 成本。

## 奚童双 Provider 预设 (xitong-preset)

**位置**：`src/config/presets.ts:30-53`

```typescript
{
  id: 'xitong',
  label: '奚童',
  description: 'MIMO 对话 + SiliconFlow 搜索，一个配置全搞定',
  provider: 'xiaomi',
  roleAssignments: {
    chat:        'mimo-v2.5-pro',
    router:      'mimo-v2.5',
    pageindex:   'mimo-v2.5',
    proposition: 'mimo-v2.5',
    tts:         'mimo-v2.5-tts-voicedesign',
  },
  secondaryProvider: 'siliconflow',
  secondaryRoleAssignments: {
    embedding: 'Qwen/Qwen3-Embedding-0.6B',
    reranker:  'Qwen/Qwen3-Reranker-0.6B',
  },
}
```

### 双 Provider 的必要性

`xiaomi` 不支持 `embedding` 和 `reranker` 能力（看 7 服务商能力矩阵）——**只用小米跑不了搜索**。所以需要第二个 Provider 来补这两个能力。

`siliconflow` 同时支持 `chat` / `embedding` / `reranker`——**作为副 Provider 同时满足"用嵌入 + 重排"两个角色**。

### 用户视角

应用预设后，自动填好 7 个角色（chat / router / pageindex / proposition / tts / embedding / reranker），剩 `imagegen` 留给用户自己决定（默认 null）。

`detectCurrentPreset()`（`presets.ts:92-115`）当用户手动修改了任何角色，会检测出"已偏离预设"——UI 提示用户"已自定义"。

## 降级链 (fallback)

**8 个角色 + 双 Provider + 各种可选**——降级链较长。**两阶段降级**：

### 阶段 1：单角色降级

| 角色 | null 行为 | 降级结果 |
|---|---|---|
| `embedding` | null | 跳过向量化，搜索仅用 BM25 |
| `reranker` | null | 跳过 Stage 7 重排，搜索质量略降 |
| `proposition` | null | 不提取命题卡片（已默认禁用） |
| `tts` / `imagegen` | null | 禁用对应功能入口 |
| `chat` / `router` / `pageindex` | null | **不降级**——抛错提示用户配 |

### 阶段 2：副 Provider 缺失

`buildRolesFromPreset(preset, withSecondary = true)`（`presets.ts:68-85`）——当 `withSecondary = false` 时，**只填主 Provider 角色**，`embedding` / `reranker` 自动 null。

**使用场景**：
- 副 Provider Key 缺失（用户没配）
- 用户主动切回"只用主 Provider"
- 检测到"主 Provider 已够用"（如只用对话功能）

### `fallbackApiKey` 内部降级

仅 `xiaomi` 的主 Provider 支持 `fallbackApiKey`——`apiKey` 失败时自动切到 `fallbackApiKey`，用户无感（看 `src/config/providers.ts` 里的 XiaomiMIMOClient 实现）。

## 用户调试指南 (debug)

### Q1: "我填了 embedding 为何搜索还是没向量化？"

**排查路径**：
1. 看 `settings.json` 里 `roles.embedding` 是否真的不为 null
2. 看 `book-meta.json` 里 `embedding` 字段——重新索引前都是空
3. **重新索引该书**——embedding 不会"补建"

### Q2: "我切换 Provider 后所有角色都变成自定义"

**原因**：`detectCurrentPreset()` 是**严格匹配**——任何角色偏离就返回 null。

**修复**：要么点"重置为预设"，要么手动调成预设的精确模型名。

### Q3: "为什么我配了 7 个服务商还是不能加命题卡片？"

**原因**：`proposition` 角色**默认 null**——**命题卡片当前已禁用**（`docs/architecture/书籍索引系统.md` 有说明）。

**修复**：填一个 chat 角色模型到 `proposition`，**+ 改 `library-view.ts` 的 `PROPOSITION_ENABLED = true` + 改 `book-indexer.ts` 的启用条件**。

### Q4: "我配了 `imagegen` 但 visualizer 还是不工作"

**原因**：`hasDiagramIntent()` 路由判断（`docs/architecture/系统鸟瞰.md` 风险章节提到）**永远返回 false**——图表生成已迁到 Hermes MCP，`imagegen` 角色不再消费。

**修复**：清理死分支（这是技术债，暂未做）。

### Q5: "为什么 router 跑得特别慢？"

**原因 1**：用户把 `router` 配成了 chat 同款大模型（应该配便宜小模型）。

**原因 2**：router 配的模型不支持快响应（如 thinking 模型触发慢思考）。

**调试**：看 LangSmith trace S0 节点耗时 + token 用量。

### Q6: "我手动改了 settings.json 但没生效"

**原因**：
1. Obsidian 缓存了旧配置——重启 Obsidian
2. 改的是 `.claude/plugins/...` 的副本而非 vault 里的真实 `data.json`
3. **JSON 格式错**——下次保存时整个 settings 备份被覆盖

**修复**：先备份 `data.json`，再改，再用插件设置界面"重置"触发一次保存。
