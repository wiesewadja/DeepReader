## 总览：一条从"一本书的文件"到"可被 Agent 检索的索引"的全链路

```
用户拖入 / 选中 PDF/EPUB
         │
         ▼
  ┌──────────────┐  Library / Sidebar 命令触发
  │  indexBook() │ ← src/pageindex/book-indexer.ts:122
  └──────┬───────┘
         │ Step 0: 验证文件 → 生成内容哈希 bookId
         │ Step 1: PageIndex.fromPdf / fromEpub（5–70%）
         │         ├─ PDF: MinerU 云 API  → outline 快路径 / LLM TOC / OCR 兜底
         │         └─ EPUB: AdmZip + Turndown + block ID 生成
         │ Step 1.5: 封面保存（早保存，UI 提前可见）
         │ Step 1.6: 下载 PDF 图片（MinerU CDN）
         │ Step 2: 导出 Markdown（70–80%）
         │ Step 3: 元数据 + tree.json（82–85%）
         │ Step 4: L0/L1/L2 向量化（87–92%，可选）
         │ Step 5: BM25 索引（94–97%）
         │ Step 6: 命题卡片（97%，已禁用）
         │ Step 8: 完成（100%）
         ▼
  .obsidian/plugins/<pluginId>/pageindex/<bookId>/
    ├── tree.json              树 + nodeFileMap
    ├── book-meta.json         元数据
    ├── bm25.json              倒排索引
    ├── vectors.jsonl          L0/L1/L2 向量
    ├── chunks.jsonl           段落原文
    ├── traces/<bookId>.{log,json}  执行追踪
    └── .indexing.json         临时进度（成功即删）
         │
         ▼
  Agent 检索时调用 searchBookV2() → 8 阶段混合搜索
  → matchedBlocks（聚焦到 ^block_id）
  → FrontendAgent 在 LLM 输出中插入 [[file#^block|alias]] 链接
```

**统一入口**：`src/pageindex/unified.ts` 提供 `docToIndex()` / `docToObsidian()`，
按扩展名自动派发到 PDF / EPUB / Markdown 管线。

## 路径管理：dev / daily 隔离 + 迁移

**位置**：`src/pageindex/paths.ts`

### 路径族

| 形态 | 说明 |
|---|---|
| `.pageindex/` | **历史**路径，已废弃 |
| `.obsidian/plugins/<pluginId>/pageindex/` | **现行**路径，跟随 pluginId |
| `dev` 构建 pluginId | `deepreader-dev` → `.obsidian/plugins/deepreader-dev/pageindex/` |
| `daily` 构建 pluginId | `deepreader` → `.obsidian/plugins/deepreader/pageindex/` |

### 隔离机制：`PAGEINDEX_DIR` Proxy 黑魔法

```typescript
// 87 个调用点用 ${PAGEINDEX_DIR}/xxx 拼接，无需改写即可跟随当前 pluginId
export const PAGEINDEX_DIR: string = new Proxy({} as object, {
  get(_target, prop) {
    if (prop === 'toString' || prop === 'valueOf' || prop === Symbol.toPrimitive) {
      return () => getPageindexDir();
    }
    return undefined;
  },
}) as unknown as string;
```

**`setActivePluginId(pluginId)`** 在 `main.ts onload` 中调用，决定当前激活的 pluginId。

### 迁移：`migratePageindexPath()` + `migrateBookIndexes()`

`src/pageindex/migration.ts` 一次性把旧 `.pageindex/` 数据迁到新位置，**幂等**。

`src/pageindex/book-indexer.ts: migrateBookIndexes()` 把 **path-hash bookId → content-hash bookId**：
- 旧 ID 不可靠（文件被移动/重命名即失效）
- 新 ID = SHA-256(前 64KB + 文件大小) 取前 8 字符
- 旧索引数据自动重命名目录并修复 `catalog.json` 引用

### 路径函数

| 函数 | 用途 |
|---|---|
| `getPageindexDir()` | vault 相对路径（动态） |
| `PAGEINDEX_DIR` | Proxy 常量，模板字符串拼接用 |
| `pageindexPaths(pluginId)` | 静态显式路径族（推荐新代码用） |
| `getPageindexRoot(vaultPath)` | 绝对路径根 |
| `getBookDir(vaultPath, bookId)` | 单本书目录 |
| `getCatalogPath(vaultPath)` | `catalog.json` 绝对路径 |
| `getLastPagesPath(vaultPath)` | `last-pages.json` 绝对路径 |

## 主编排：`indexBook()` 8 步管线

**位置**：`src/pageindex/book-indexer.ts:122`

```
B0  validate        验证文件存在 → 清理旧的 .indexing.json → 创建追踪
B1  parse_document  PageIndex.fromPdf / fromEpub (5–70%)
B1.5 save_cover     封面早保存（EPUB 解析时已存，PDF 渲染首页）
B1.6 download_images 下载 PDF 图片到 images/  (70%)
B2  export_markdown 导出 Markdown + nodeFileMap  (70–80%)
B3  build_meta      book-meta.json + tree.json   (82–85%)
B4  vectorize       L0/L1/L2 向量化（可选）       (87–92%)
B5  build_bm25      BM25 倒排索引                 (94–97%)
B6  extract_propositions 命题卡片（已禁用）         (97%)
B8  complete        删 .indexing.json            (100%)
```

### 关键设计

- **进度回调两层**：`onProgress` 回调到 UI + `reportProgress` 持久化到 `.indexing.json`（UI 关闭重开可恢复）
- **`try-finally` 保证清理**：失败时保留 `.indexing.json` 让 `loadIndexes` 显示"failed"状态
- **`.indexing.json` step 命名规避**：PageIndex 内部用 `complete`，book-indexer 映射为 `parse_complete` 避免 UI 误判 100%
- **tracer 全程**：每个 B 阶段配 `tracer.startPhase / endPhase`，LLM 调用 `tracer.recordLlmCall`，失败 `tracer.failPhase`

### 进度回调持久化

```typescript
const reportProgress = (progress: { percent, step, stepLabel, message? }) => {
  options.onProgress?.(progress);
  // 异步写盘（fire-and-forget）
  fs.writeFile(indexingStatusPath, JSON.stringify({ bookId, filePath, ...progress }))
    .catch(() => {});
};
```

## PDF 解析（3 路径）

**位置**：`src/pageindex/parsers/pdf.ts` → `parsers/mineru.ts` → `core/toc.ts` → `core/tree.ts`

```
输入 PDF
  │
  ├─ ① MinerU 云 API（主路径）
  │   parsePdf() → MineruClient.parse()
  │     │
  │     ├─ outline 高质量？（≥5 条目 + ≥60% 页面覆盖）
  │     │   YES → processPdfWithOutline()  [免 LLM 快路径]
  │     │
  │     └─ outline 不高质量
  │         → processPdfPages()  [LLM TOC 路径，6 阶段]
  │           失败且有 outline → 回退 processPdfWithOutline()
  │
  ├─ ② OCR 兜底（MinerU 失败 或 强制 OCR 模式）
  │   parsePdfWithOcr() → pdftocairo 转图片 → GLM-OCR
  │
  └─ 返回 PageIndexResult
```

### `processPdfPages()` 6 阶段

| 阶段 | 名称 | 内容 |
|---|---|---|
| 1 | `detecting_toc` | `checkToc()` 扫描前几页找目录 |
| 2 | `parsing_structure` | 三路分发：无 TOC / TOC 无页码 / TOC 有页码 |
| 3 | `verifying_pages` | `verifyToc()` 验证页码准确率，<60% 触发降级重试链 |
| 4 | 树构建 | `buildTree()` + `addNodeText()` + `processLargeNodesRecursively()` |
| 5 | `generating_summaries` | 每 8 个节点一批并行调 LLM |
| 6 | `generating_description` | 生成一句话文档描述 |

### 降级重试链

```
有页码 TOC  →  无页码 TOC  →  从内容生成  →  书签回退
```

准确率 ≥60% 时 `fixIncorrectToc()` 修正错误条目，最多重试 2 次。

### 备用 PDF 解析：`pdf-to-markdown.ts`

`src/pageindex/parsers/pdf-to-markdown.ts`（721 行）是另一条独立 PDF→Markdown 路径，
用于 MinerU 不可用时的兜底；走 pdfjs-dist 文本提取 + Turndown。

## EPUB 解析

**位置**：`src/pageindex/parsers/epub.ts`（1222 行）

```
EPUB 文件 (ZIP)
  │
  ├─ AdmZip 解压
  ├─ META-INF/container.xml → 定位 OPF 文件
  ├─ 解析 OPF:
  │   ├─ 元数据: title, creator
  │   ├─ manifest map: id → href
  │   ├─ spine: 阅读顺序
  │   └─ 封面图片提取（EPUB 3.0 properties="cover-image" 或 EPUB 2.0 <meta name="cover">）
  │
  ├─ 按阅读顺序遍历章节:
  │   ├─ 读取 HTML 内容
  │   ├─ extractTextFromHTMLWithBlocks() → Turndown HTML → Markdown + block ID 生成
  │   └─ 章节标题提取 (h1 > h2 > ...)
  │
  ├─ 跳过纯图片/封面页
  └─ 返回 EpubInfo { title, author, chapters[], coverImage }
```

### Block ID 生成

`createTurndownServiceWithBlocks()` 为每个段落生成稳定 block ID：

- **优先使用原始 HTML `id`**（替换 `_` 为 `-`）
- **否则生成** `p{chapterIndex}-{counter}` 格式
- 维护 `blockMap: Map<anchorId, blockId>` 和 `blocks: string[]`

### HTML → Markdown 转换规则

| HTML 元素 | Markdown 输出 | 说明 |
|---|---|---|
| `<img>` | `![alt](src)` | 保留图片引用 |
| `<a href="...#fn">` | `[^N]` | 脚注链接 |
| `<a href="chapter#anchor">` | `[[file#^anchor\|text]]` | Obsidian 双链 |
| `<p>` | 段落 + `^blockId` | 自动生成 block ID |
| `<li>` | 列表项 + `^blockId` | 自动生成 block ID |
| `<ruby>` | `{base\|ruby}` | CJK 注音 |

### 大章节切分

`splitLargeEpubPages(pages, chapters)`（同文件）按 token 阈值切分超大章节：

- 超过 `EPUB_SPLIT_THRESHOLD` 的页面按 `EPUB_SPLIT_PATTERN` 拆
- 解析首行 heading 作为新章节标题（去除 `## / 第X章 / Chapter N / Part X` 前缀后标准化）
- 防御性回退：`cleanTitle` 清空时回到 `chapter.title`

### 标题分类

`classifyTitle(title) → part / chapter / section / special / other`，
`calculateLevels` 计算层级：篇(0) / 章(0-1) / 节(2)。

### 内容清洗

- `fixAbnormalAsterisks`：合并分散单字符加粗（`观**念**检**核**` → `**观念检核**`）
- 标题行清洗：去除多余 `*` 和 `-`

## Markdown 导出

**位置**：`src/pageindex/exporters/`

### PDF 导出：`pdf-to-obsidian.ts`

```
TreeNode[] (解析结果)
  │
  ├─ 父节点 → summary callout + 子节点链接列表
  ├─ 叶节点 → 全文 + ^blockId 标记 + 导航链接
  │
  │   每个 TreeNode → 一个 .md 文件
  │   block ID 格式: s{sectionIndex}-{counter}
  │
  ├─ MOC 文件 → YAML frontmatter + 目录树 + 作者/来源
  │
  └─ 返回 nodeFileMap: Record<nodeId, fileName.md>
```

### EPUB 导出：`epub-to-obsidian.ts`

- 章节层级计算：篇(0) / 章(0-1) / 节(2)
- 图片提取：保留原始目录名（images/media/assets）
- 内容清洗：修复异常星号格式 + 标题行
- 内部链接修复：
  - `[[originalBase#anchor]]` → `[[newFileName#^blockId]]`（跨章节）
  - `[[#^anchor|text]]` → `[[fileName#^blockId|text]]`（同章节内）
- 写 frontmatter：title / source / type=epub / tags / author / index_id

### EPUB 适配器：`adapter.ts`

`processChapters()` 处理大章节：
- 按 token 限制拆分为多个虚拟章节
- 可选 LLM 为每个虚拟章节生成摘要
- `exportEpubToObsidian()` 是 `unified.ts` 调用的入口

### 统一导出：`unified.ts: docToObsidian()`

```typescript
function detectDocType(input, hint) {
  if (hint) return hint;
  const ext = path.extname(input).toLowerCase();
  switch (ext) {
    case ".pdf": return "pdf";
    case ".epub": return "epub";
    case ".md":
    case ".markdown": return "markdown";
  }
}
```

`docToObsidian(input, options)` 按扩展名自动派发到 `exportPdfToObsidian` / `exportEpubToObsidian` / `mdToTree`。
返回 `ObsidianExportResult { mocPath, notes, nodeFileMap, treeNodes }`。

## 元数据 / tree.json 合并

`book-indexer.ts: B3 build_meta` 阶段：

1. **`book-meta.json`**：版本化元数据（v3），包含：
   - 基础：title / author / fileType / indexedAt
   - 嵌入：`embedding { provider, model, dimensions }`
   - 命题：`propositions { enabled, totalCards, model, generatedAt }`
2. **`tree.json`**：唯一数据源（**single source of truth**），包含：
   - 标题、exportName、docDescription、source
   - 完整树结构 `structure: TreeNode[]`（含 text + summary + startIndex + endIndex）
   - `nodeFileMap: Record<nodeId, fileName.md>`

### tree.json 合并细节

对 EPUB：`structure` 直接来自 `parseResult.structure`（flat list）；
但 `_hierarchicalTree`（EPUB 层级树）会被合并进去——`enrichNode()` 从 flat 中取 `text/summary/startIndex/endIndex`，
覆盖 hierarchicalTree 的 0-based 索引（避免与 flat 的 1-based 冲突）。

## 三级向量化 L0 / L1 / L2

**位置**：`src/pageindex/book-indexer.ts: vectorizeAllLevels()`（800 行）

```
L0  书籍级     bookTitle + "\n" + bookSummary              → 1 条向量
L1  章节摘要级  chapterTitle + "\n" + chapterSummary         → N 条向量
L2  段落块级    章节文件 → splitByBlockIds → mergeToChunks   → N 条向量
```

### L2 段落分块

`src/pageindex/chunker.ts`：

1. `splitByBlockIds()` — 按 `^blockId` 标记拆分段落
2. `classifyType()` — 分类段落：heading / body / list / quote
3. `mergeToChunks()` — 合并为 300–800 字符的 chunk
   - 目标大小 300 字符，最大 800 字符
   - 超长段落按句号/逗号/分号断句拆分
   - chunkId 格式: `{nodeId}_{firstBlockId}`

### Embedding 生成

`src/pageindex/vault/vectors.ts: generateEmbeddings()`：

- 支持 provider：openai, ollama, lmstudio（`provider: 'local'` = 跳过向量化）
- 批量嵌入，默认 `batchSize=32`
- BGE 模型截断到 400 字符，其他模型 8000 字符
- 空文本替换为占位符

### 存储格式

| 文件 | 每行 |
|---|---|
| `vectors.jsonl` | `{chunkId, nodeId, blockIds, type, level, vector}` |
| `chunks.jsonl` | `{chunkId, nodeId, blockIds, text, type}` |

### 降级

- `provider === 'local'` → 跳过向量化
- API 失败 → `bookMeta.embedding = undefined` + UI 显示"使用纯 BM25"
- 索引继续完成，不中断

## Vault 编译管线（`compileVault`）

**位置**：`src/pageindex/vault/compiler.ts`（357 行）

> 与"书籍索引"不同，编译管线针对**用户整个 vault 的笔记**做：
> 概念抽取 → 标签合并 → 重组目录 → 增强 frontmatter → 嵌入向量 → 生成 `_总目录.md` 和 MOC。

```
Step 1  scan              扫描 vault 目录结构，分类 timeline / topic / book / mixed
Step 2  reorg             timeline 类目录按 planReorg() 重组（dry-run 默认）
Step 3  parse structure   收集每条笔记的 # 标题 + 首段 200 字
Step 4  extract concepts  LLM 批量抽取 { tags, topic, wikiLinks, relatedConcepts }
                          首次运行做第二轮（合并后标签约束）
Step 5  generate index    写 _总目录.md + topic MOC + 每个 book 目录的 _目录.md
Step 6  enhance in-place  备份到 .pageindex/backup/，合并 frontmatter，插入 wiki 链接
Step 7  embed             批量生成嵌入，写 vectors.jsonl（与书籍索引同名空间）
```

### 状态持久化

`compiler-state.json` 跟踪 `phase1CompletedAt` 和 phase2 队列，支持中断后恢复。
**首次运行强制 dry-run**，避免误操作。

### 与书籍索引的关系

- 共享 `vectors.jsonl` 命名空间（同一目录）
- 共享 `embedding-cache.ts`（避免重复嵌入）
- **不冲突**：书籍级 vector 是 `{nodeId, level, ...}`，笔记级是 `{nodeId=file, level=L1, type=summary}`

## 统一入口：`unified.ts` + 归档 `archive.ts`

### `unified.ts`（283 行）

```typescript
import { docToIndex, docToObsidian } from "./pageindex/unified.js";

const result = await docToObsidian("/path/to/book.pdf");
// 自动检测 .pdf → 走 PDF 管线
// 自动检测 .epub → 走 EPUB 管线
// 自动检测 .md → 走 mdToTree 管线
```

## 执行追踪：`index-tracer.ts`

**位置**：`src/pageindex/index-tracer.ts`（361 行）

### 追踪结构

`traces/{exportName}.log`：逐行 JSON（追加写）
`traces/{exportName}.json`：聚合摘要（一次写）

### 事件类型

| 事件 | 字段 |
|---|---|
| `index_start` | bookId, title, filePath, fileType, config |
| `phase_start` | phase name |
| `phase_end` | phase, durationMs, success, stats?, error? |
| `llm_call` | phase, model, inputTokens, outputTokens, durationMs |
| `embed_call` | model, durationMs, inputTokens, batchSize |
| `path_decision` | phase, decision, reason |
| `index_end` | success, error?, totalDurationMs |
| `llm_summary` | totalCalls, byModel, totalDurationMs |

### 零开销模式

`INDEX_TRACE_ENABLED=false` 时使用 `NoopIndexTracer`，所有方法都是空实现。

### 用法

- 调试某本书为什么索引慢：看 `traces/{name}.log` 的 `phase_start/end` 时间戳
- 比对两本书 LLM 调用成本：看 `llm_summary.byModel`
- 失败诊断：看 `phase_end { success: false, error }`

## 错误处理与降级策略 — error-handling

| 错误类型 | 处理方式 |
|---|---|
| 文件不存在 | 立即抛出 `IndexError(FILE_NOT_FOUND)` |
| MinerU API 失败 | 自动降级到 OCR 路径 |
| TOC 准确率 < 60% | 降级重试链：有页码 → 无页码 → 无 TOC → 书签回退 |
| 向量化失败 | 降级为纯 BM25，索引继续完成 |
| 命题提取失败 | 记录错误到 book-meta.json，索引继续完成 |
| 整体失败 | `try-finally` 确保 `.indexing.json` 被保留（UI 显示 failed） |
| OCR API 错误 | 单页失败返回空字符串，不中断整体 |
| EPUB XML 注释不规范 | 主动清洗而非报错 |
| 旧路径数据 | 启动时 `migratePageindexPath` 一次迁移（幂等） |
| 旧 bookId（path-hash） | `migrateBookIndexes` 重命名为 content-hash |

### 错误码

`IndexErrorCode`（在 `book-types.ts`）：
- `FILE_NOT_FOUND`
- `INDEX_INCOMPLETE`
- `MD_PARSE_ERROR`
- ...

每个 `IndexError` 带 `userMessage` 和 `repairAction`，直接显示给用户。
