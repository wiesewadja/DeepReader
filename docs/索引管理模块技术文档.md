## 一、模块概述

索引管理模块是 DeepReader 的核心模块，负责将 PDF/EPUB 文档转换为可检索的向量索引。该模块采用异步任务架构，支持后台处理、进度追踪和实时状态查询。

### 核心功能
- PDF/EPUB 文档索引创建
- 索引任务管理（创建、查询、取消、删除）
- 索引元数据管理
- 阅读进度追踪
- 索引列表缓存

### 2.3 扫描型 PDF 处理流程

当索引 PDF 文件时，系统会自动检测是否为**扫描型 PDF（视觉密集型）**，并根据检测结果决定是否使用 OCR 处理。

#### 2.3.1 视觉类型检测

**检测时机**: 索引步骤 1.5（在文件验证之后、LLM 配置之前）

**检测函数**: `pageindex.pdf.ocr.detect_pdf_type()`

**检测参数**:
| 参数 | 默认值 | 说明 |
|------|--------|------|
| `sample_pages` | 10 | 采样检测的页数 |
| `text_threshold` | 500* | 每页最小字符数阈值 |
| `image_threshold` | 0.3 | 图片面积占比阈值 (30%) |

> *注：默认值为 500，但 `VisualDetector` 类中默认值为 50，实际使用从 `settings` 读取

**检测逻辑** (满足任一即判定为视觉密集型):

```
条件 1: 文本稀疏
    avg_text_per_page < text_threshold (默认 500 字符/页)

条件 2: 图片密集
    image_density > image_threshold (默认 30%)
```

**返回结果** (`VisualDetectionResult`):
```python
@dataclass
class VisualDetectionResult:
    is_visual_heavy: bool      # 是否为视觉密集型
    text_density: float         # 平均每页字符数
    image_density: float       # 图片面积占比 (0-1)
    sampled_pages: int         # 采样的页数
    reason: str                 # 判断依据
```

#### 2.3.2 OCR 自动触发

在 `page_index_main()` 函数内部，会进行二次检测：

```python
# 计算平均每页文本长度
avg_text_per_page = total_text_length / total_pages

# 如果每页少于 50 字符，判定为扫描档
is_likely_visual = avg_text_per_page < 50
```

**触发条件**: `avg_text_per_page < 50` 字符/页

**OCR 引擎**: PaddleOCR (通过 `PaddleOCRExtractor`)

**OCR 处理流程**:
```
1. 使用 PyMuPDF 打开 PDF
2. 对每一页调用 PaddleOCR 提取文本
3. 用 OCR 文本替换原始空文本
4. 重新计算 tokens
5. 继续后续的目录检测和章节解析
```

## 三、API 端点详解

### 3.1 创建索引

**端点**: `POST /api/index`

**请求参数** (IndexRequest):

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `file_id` | string | 否* | 上传文件的 ID（二选一） |
| `path` | string | 否* | 文件路径（二选一） |
| `config_name` | string | 否 | 已保存的配置名称 |
| `llm_provider` | string | 否 | LLM 提供商 (deepseek/openai/custom) |
| `llm_model` | string | 否 | LLM 模型名称 |
| `deepseek_api_key` | string | 否 | DeepSeek API 密钥 |
| `openai_api_key` | string | 否 | OpenAI API 密钥 |
| `api_url` | string | 否 | 自定义 API 地址 |
| `max_pages_per_node` | int | 否 | 每节点最大页数 |
| `max_tokens_per_node` | int | 否 | 每节点最大 token 数 |
| `if_add_node_summary` | bool | 否 | 是否生成章节摘要 |
| `enable_text_formatting` | bool | 否 | 是否启用文本格式化 |

**响应** (IndexResponse):
```json
{
  "status": "success",
  "task_id": "task_abc123def456",
  "message": "索引任务已创建"
}
```

**流程说明**:
1. 验证参数（file_id 或 path 必须提供一个）
2. 检查文件是否存在
3. 速率限制检查（每 10 分钟最多 20 个任务）
4. 提取 LLM 配置（优先级：请求参数 > 配置文件 > 默认值）
5. 创建后台任务，立即返回 task_id

## 四、核心服务详解

### 4.1 indexer.py - 核心索引逻辑

**主要函数**:

#### `async def index_pdf(pdf_path, storage_dir, progress_callback, **kwargs)`
索引入口函数，使用 `ThreadPoolExecutor` 在后台线程执行 CPU 密集型任务。

#### `_index_pdf_sync(...)`
同步索引逻辑，包含 6 个步骤：

| 步骤 | 函数 | 进度 | 说明 |
|------|------|------|------|
| 1 | `_validate_pdf_file` | 10% | 验证文件存在和大小 |
| 2 | `_check_llm_config` | 20% | 检查 LLM API 配置 |
| 3 | `_setup_pageindex_config` | 30% | 初始化 PageIndex 配置 |
| 4 | 创建 LLM 客户端 | 40% | 创建 UnifiedLLM 实例 |
| 5 | `_parse_pdf_structure` | 50% | 使用 PageIndex 解析结构 |
| 6 | `_store_to_chromadb` | 80% | 向量存储 |

#### `_parse_pdf_structure(...)`
- 调用 `page_index_main()` 解析 PDF 结构
- 支持视觉密集型 PDF 检测（OCR 需求）
- 返回树状结构 (`tree_result.get("structure")`)

#### `_extract_nodes_from_tree(...)`
从 PageIndex 树结构中提取章节节点：

```python
def _extract_nodes_from_tree(tree, parent_section, level, doc_type, formatter):
    nodes = []
    # 1. 获取节点信息 (title, pages, text, summary)
    # 2. 向量化使用摘要（更好的语义表示）
    # 3. 原始文本保存在 metadata 中（供导出使用）
    # 4. 递归处理子节点
    return nodes
```

**节点数据结构**:
```python
{
    "id": "node_xxx",
    "text": "【章节标题】\n章节内容摘要...",
    "metadata": {
        "section": "第1章 > 1.1 节",
        "level": 2,
        "page": 10,
        "start_index": 10,
        "end_index": 15,
        "node_name": "章节标题",
        "node_id": "node_xxx",
        "summary": "LLM生成的摘要",
        "original_text": "原始文本（格式化后）"
    }
}
```

#### `_store_to_chromadb(...)`
- 创建 ChromaDB 集合
- 向量化并存储文档
- 记录集合元数据（doc_type, node_count, indexing_method 等）

#### `_save_metadata(...)`
- 保存元数据到 JSON 文件
- 包含完整树结构、章节节点、阅读进度字段
- PDF: 记录总页数；EPUB: 使用章节数作为"页数"

## 八、错误处理

### 8.1 常见错误

| 错误 | 原因 | 处理方式 |
|------|------|----------|
| `File not found` | 文件路径不存在 | 400 Bad Request |
| `Rate limit exceeded` | 超过速率限制 | 429 Too Many Requests |
| `LLM API key is required` | 未配置 API Key | 500 Internal Server Error |
| `No section nodes extracted` | 解析失败，无章节 | 500 Internal Server Error |

### 8.2 任务状态

| 状态 | 说明 |
|------|------|
| `pending` | 等待执行 |
| `processing` | 执行中 |
| `completed` | 执行成功 |
| `failed` | 执行失败 |
