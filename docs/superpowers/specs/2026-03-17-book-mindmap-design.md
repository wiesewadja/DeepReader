# Book Mindmap 书籍思维导图设计文档

> 创建日期: 2026-03-17
> 状态: 设计完成，待实现

## 1. 概述

### 1.1 背景

DeepReader 已有 `mindmap` skill 和 `excalidraw` tool，可以生成任意主题的思维导图。但对于整本书的思维导图，现有方案存在不足：

- 简单罗列章节目录，而非提取知识结构
- 缺乏书籍类型判断，无法针对不同类型优化
- 大型书籍处理不够智能

### 1.2 目标

创建专用的 `book-mindmap` skill，实现：

1. **知识结构提取**：提取核心概念和关系，而非简单罗列章节
2. **类型自适应**：根据书籍类型自动选择合适的结构模板
3. **分层处理**：支持高层概览和按需深入
4. **节点跳转**：点击节点可跳转到对应章节

### 1.3 核心原则

**书籍思维导图 ≠ 章节目录图**

- ❌ 错误：简单罗列章节标题
- ✅ 正确：提取知识结构，呈现概念关系

## 2. 书籍类型分类

采用《如何阅读一本书》的分类框架：

| 类型 | 描述 | 示例 |
|------|------|------|
| **理论性** | 哲学、科学、历史等探讨"是什么/为什么"的书籍 | 《存在与时间》、《物种起源》 |
| **实用性** | 手册、指南、商业等探讨"怎么做"的书籍 | 《高效能人士的七个习惯》、《编程珠玑》 |
| **叙事性** | 小说、传记、历史叙事等讲述故事的书籍 | 《百年孤独》、《史蒂夫·乔布斯传》 |

### 2.1 类型判断规则

**优先级**：

1. **元数据优先**：检查索引元数据中的书籍分类信息
2. **Agent 推断兜底**：基于目录结构和章节标题推断

**推断规则**：

| 类型 | 目录特征 | 章节标题特征 |
|------|----------|--------------|
| 理论性 | "理论"、"原理"、"哲学"；递进论证结构 | "论"、"分析"、"研究" |
| 实用性 | "指南"、"手册"、"方法"；步骤/模块结构 | "如何"、"步骤"、"技巧" |
| 叙事性 | "章"、"卷"、"部"；时间/情节结构 | 人物名、地名、事件名 |

**默认值**：无法判断时默认为**理论性**

## 3. 结构模板

### 3.1 理论性书籍 → 问题驱动结构

**核心问题识别**：
- 从书名、副标题、序言提取核心问题
- 从章节标题提取子问题

**结构模板**：

```
书名（回答什么问题？）
├── 核心问题1
│   ├── 论点/观点
│   └── 论据/证据
├── 核心问题2
│   └── ...
└── 核心结论
```

**提取指令**：
- 识别作者试图回答的核心问题
- 找出主要论点和支撑论据
- 标注论证的逻辑关系

### 3.2 实用性书籍 → 目标驱动结构

**核心目标识别**：
- 从书名、副标题提取核心目标
- 从章节标题提取子目标/步骤

**结构模板**：

```
书名（达成什么目标？）
├── 目标1
│   ├── 步骤/方法
│   └── 要点/注意事项
├── 目标2
│   └── ...
└── 总结/检查清单
```

**提取指令**：
- 识别读者能达成的目标
- 找出具体步骤和方法
- 提取关键要点和常见问题

### 3.3 叙事性书籍 → 情节驱动结构

**主线识别**：
- 从目录识别叙事结构（起承转合）
- 识别主要人物和事件

**结构模板**：

```
书名（讲述什么故事？）
├── 主要人物
│   └── 人物关系
├── 情节主线
│   ├── 起因
│   ├── 发展
│   ├── 高潮
│   └── 结局
└── 主题/寓意
```

**提取指令**：
- 识别主要人物及其关系
- 梳理情节发展脉络
- 提取主题和深层含义

## 4. 处理流程

### 4.1 两阶段处理

#### 阶段一：快速扫描

**目标**：确定书籍类型，提取候选框架

**输入**：
- 目录结构（`get_toc`）
- 章节摘要（如果索引时生成）

**输出**：
- 书籍类型（理论性/实用性/叙事性）
- 一级结构框架（3-7 个核心节点）
- 每个节点的来源章节

**处理逻辑**：

```
1. 调用 get_toc 获取目录
2. 判断书籍类型（元数据或推断）
3. 根据类型提取一级结构：
   - 理论性：识别核心问题和主要论点
   - 实用性：识别主要目标和模块
   - 叙事性：识别主线和主要部分
4. 记录每个节点对应的章节范围
```

#### 阶段二：精炼组织

**目标**：组织成完整的思维导图结构

**输入**：
- 阶段一的输出
- 用户选择的深度（高层/详细）

**输出**：
- 完整的思维导图 JSON 结构
- 每个节点的跳转信息（章节标题）

**处理逻辑**：

```
1. 根据书籍类型选择结构模板
2. 遍历一级节点对应的章节，提取子节点
3. 组织成 mindmap 结构：
   - topic: 书名
   - branches: 一级节点
   - children: 二级/三级节点
4. 为每个节点附加跳转信息
5. 调用 excalidraw tool 生成
```

### 4.2 分层处理机制

#### 高层概览（默认）

**适用场景**：首次生成，或大型书籍

**处理方式**：
- 只分析一级章节
- 生成 3-7 个核心节点
- 每个节点代表一个"部分"或"主题群"

**示例**：

```
《深度学习》
├── 基础理论
├── 神经网络
├── 卷积网络
├── 循环网络
└── 实践应用
```

#### 深入展开（按需）

**触发方式**：用户指定展开某个部分

**处理方式**：
- 只分析指定部分对应的章节
- 生成该部分的详细结构
- 生成独立导图文件

**示例**（展开"神经网络"部分）：

```
《深度学习》- 神经网络详解
├── 感知机
│   └── 单层感知机
├── 多层网络
│   └── 前向传播
├── 激活函数
│   ├── Sigmoid
│   └── ReLU
└── 反向传播
    └── 梯度下降
```

## 5. 节点跳转功能

### 5.1 数据结构

```typescript
interface MindmapNode {
  label: string;           // 节点显示文本
  children?: MindmapNode[];
  // 跳转信息
  jumpInfo?: {
    chapterTitle: string;  // 章节标题，用于链接
  };
}
```

### 5.2 Excalidraw 实现方式

节点文本格式：`概念名称 [[章节标题]]`

**示例**：

```json
{
  "label": "神经网络 [[第3章 神经网络基础]]",
  "children": [
    { "label": "感知机 [[第3章 神经网络基础]]" },
    { "label": "激活函数 [[第3章 神经网络基础]]" }
  ]
}
```

### 5.3 Agent 处理逻辑

```
1. 提取概念时，记录来源章节标题
2. 组织 mindmap 结构时，将章节标题附加到节点
3. 调用 excalidraw tool 时，节点文本格式为 "概念 [[章节名]]"
```

## 6. Skill 定义

### 6.1 基础信息

```yaml
---
name: book-mindmap
description: 生成书籍知识结构思维导图 - 基于书籍类型自动选择合适的结构，提取核心知识而非简单罗列章节
keywords:
  - 书籍思维导图
  - 全书结构
  - 知识框架
  - 书籍概览
  - 整理这本书
---
```

### 6.2 触发场景

- "生成这本书的思维导图"
- "帮我梳理这本书的知识结构"
- "这本书讲了什么，画个图"
- "整理这本书的框架"

### 6.3 与 mindmap skill 的区别

| 维度 | mindmap | book-mindmap |
|------|---------|--------------|
| 适用范围 | 任意概念/主题 | 整本书 |
| 结构来源 | 用户/Agent 自由组织 | 书籍类型模板 |
| 提取方式 | 基于上下文 | 基于目录+章节分析 |
| 节点跳转 | 无 | 有（章节链接） |

### 6.4 调用示例

```json
{
  "tool": "excalidraw",
  "arguments": {
    "action": "mindmap",
    "topic": "书名",
    "branches": [
      {
        "label": "核心问题1 [[第1章 引言]]",
        "children": ["论点A", "论点B"]
      },
      {
        "label": "核心问题2 [[第3章 分析]]",
        "children": ["论据C", "论据D"]
      }
    ],
    "filename": "书名-知识结构"
  }
}
```

---

## 7. 注意事项

1. **分支数量**：控制在 3-7 个，避免布局拥挤
2. **子节点数量**：每个分支不超过 5 个子节点
3. **嵌套深度**：不超过 3 层，保证可读性
4. **节点文本**：简洁，突出核心概念
5. **触发方式**：仅用户显式命令触发
