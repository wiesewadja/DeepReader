# 设计文档：修复 TOC 死链问题

**日期**: 2026-03-19
**状态**: 待审批

## 问题背景

当 PDF/EPUB 章节内容过长时，`markdown_exporter.py` 会将其拆分成多个文件。但 TOC（目录）中的 `obsidian_link` 始终指向不带分片序号的文件名，导致链接失效。

### 当前行为

| 组件 | 行为 |
|------|------|
| **文件导出** | 分片时所有文件都带序号：`01-第一章-1.md`, `01-第一章-2.md` |
| **TOC 生成** | 链接总是 `书籍名/01-第一章.md` |

**结果**：TOC 中的链接指向不存在的文件。

## 解决方案

### 1. 修改文件命名规则

**文件**: `backend/deeppdf-api/src/deeppdf/services/markdown_exporter.py`

**修改逻辑**：第一部分不带序号，后续部分从 2 开始带序号

```
# 修改前
01-第一章-1.md  ← 第一部分
01-第一章-2.md  ← 第二部分

# 修改后
01-第一章.md    ← 第一部分（TOC 链接目标）
01-第一章-2.md  ← 第二部分
```

### 2. 添加分片导航

#### 2.1 文件顶部指示

在标题下方添加分片位置指示（仅分片文件显示）：

```markdown
# 第一章 标题

> 📖 第 1/3 部分

章节正文...
```

#### 2.2 文件底部导航

在分片文件的底部添加简单的导航链接：

```markdown
---
**来源**: [[书籍名#page=1]] (第 1-10 页)

← 上一部分：[[01-第一章]]  |  下一部分：[[01-第一章-2]] →
```

- 第一部分：只显示"下一部分"链接
- 中间部分：显示"上一部分"和"下一部分"
- 最后部分：只显示"上一部分"

### 3. 更新 frontmatter 元数据

添加分片信息：

```yaml
---
pdf_name: 书籍名
node_id: node_123
part: 1/3
total_parts: 3
---
```

## 修改范围

| 文件 | 修改内容 |
|------|---------|
| `markdown_exporter.py` | 1. 文件命名逻辑（约 5 行）<br>2. 导航链接生成（约 20 行）<br>3. frontmatter 添加 total_parts（约 2 行） |

## 不需要修改

- `reading_routes.py` - TOC 链接逻辑保持不变，因为第一部分文件名现在与链接匹配
