# DeepReader 阅读层次架构设计

## Context

DeepReader 是一款智能阅读插件，需要将《如何阅读一本书》的**四个阅读层次**融入 Agent 工作逻辑，让 Agent 具备像真人一样的阅读思维模式。

### 四个阅读层次

| 层次 | 名称 | 特点 | 工具映射 |
|------|------|------|----------|
| 1 | 基础阅读 | 认字、理解句子 | search_doc（精准查询） |
| 2 | 检视阅读 | 有限时间内抓重点 | get_toc, search_doc |
| 3 | 分析阅读 | 无限时间完整阅读 | get_chapter（多次调用） |
| 4 | 主题阅读 | 跨书比较分析 | search_read_books |

### 设计原则

- **层次递进**：高层次包含低层次能力
- **自动判断**：Agent 根据问题特征自动选择层次
- **状态可见**：用户能看到当前使用的阅读层次
- **不过度服务**：信息足够即回答，不主动升级层次

---

## Design

### Part 1：奚童人设重构

**核心变化**：将阅读方法论融入奚童的身份定义

```
奚童 = 阅读方法论专家 + Obsidian 写作者
```

**人设调整**：
- 不仅是"陪伴阅览的书童"
- 而是精通《如何阅读一本书》四层次阅读法的专业阅读者
- 能根据问题特征自动判断并切换阅读层次

**四个层次触发信号**：

| 层次 | 触发信号 | 工具使用 |
|------|----------|----------|
| 基础阅读 | 简单查询、术语解释 | search_doc（精准） |
| 检视阅读 | "讲什么"、"总结"、"概览" | get_toc, search_doc（广度） |
| 分析阅读 | "详细解释"、"为什么"、"深入" | get_chapter（多次调用） |
| 主题阅读 | "比较"、"其他书"、"关联" | search_read_books |

---

### Part 2：阅读层次的状态显示

**显示位置**：状态徽章（不嵌入消息内容）

**设计方案**：
- 在 Agent 运行时，状态区域显示当前阅读层次徽章
- 徽章样式：圆角标签，不同层次用不同颜色区分

**视觉设计**：

| 层次 | 徽章文字 | 配色 |
|------|----------|------|
| 基础阅读 | 📖 基础阅读 | 浅灰底 |
| 检视阅读 | 🔍 检视阅读 | 蓝色系 |
| 分析阅读 | 🧐 分析阅读 | 橙色系 |
| 主题阅读 | 📚 主题阅读 | 紫色系 |

**切换规则**：
- 自动根据当前使用的工具判断层次
- 如果同时使用多个层次工具，显示最高层次
- 任务完成后徽章消失

**示例场景**：
```
用户: "这本书主要讲了什么？"
→ 徽章显示: [🔍 检视阅读]
→ Agent 调用 get_toc 浏览结构

用户: "详细解释第三章的核心论点"
→ 徽章显示: [🧐 分析阅读]
→ Agent 多次调用 get_chapter 深入阅读
```

---

### Part 3：系统提示中的阅读方法论

**位置**：融入奚童人设（Identity 层），不单独成层

**设计原则**：
- 不写死规则，而是给 Agent 原则 + 示例
- 让 Agent 自主判断问题属于哪个层次
- 引导 Agent 在思考时表明当前阅读层次

**人设增强内容**（新增段落）：

```markdown
## 阅读方法论

你精通《如何阅读一本书》的四层次阅读法，会根据问题特征选择合适的阅读深度：

**检视阅读**：用户问"讲什么"、"总结"、"概览"时使用
- 目标：快速抓取重点，了解整体结构
- 策略：优先 get_toc，search_doc 用较小 top_k

**分析阅读**：用户问"为什么"、"详细解释"、"深入分析"时使用
- 目标：完整理解，咀嚼消化
- 策略：多次调用 get_chapter，逐段分析

**主题阅读**：用户问"比较"、"其他书"、"关联"时使用
- 目标：跨书比较，建立关联
- 策略：使用 search_read_books 搜索已读书库

**原则**：信息足够即回答，不主动升级层次。如果检视阅读已能回答，不必深入分析。
```

### Part 4：实现文件清单

**需要修改的文件**：

| 文件 | 修改内容 |
|------|----------|
| `humanized-types.ts` | 新增 `ReadingLevel` 类型、`TOOL_TO_READING_LEVEL` 映射、`READING_LEVEL_DESCRIPTIONS` 描述 |
| `context/builder.ts` | 在 `buildIdentityLayer()` 中添加阅读方法论段落 |
| `humanized-adapter.ts` | 新增 `determineReadingLevel()` 方法，`toHumanizedProgress()` 返回阅读层次 |
| `humanized-view.ts` | 渲染阅读层次徽章 |
| `agent-humanized.css` | 添加徽章样式（4 种配色） |

**不需要修改**：
- 工具本身（工具描述可选优化，但不影响核心功能）
- Agent 循环逻辑（阅读层次是状态展示，不影响执行流程）

**实现顺序**：
1. 类型定义 → 2. 人设更新 → 3. 适配器逻辑 → 4. UI 渲染 → 5. 样式

### Part 5：新工具建议（下期迭代）

根据《如何阅读一本书》的分析阅读和主题阅读方法论，建议新增以下工具：

#### 分析阅读工具

| 工具名 | 对应规则 | 功能说明 | 优先级 |
|--------|----------|----------|--------|
| `outline_structure` | 规则2-3 | 提取书籍整体结构和纲要 | 高 |
| `find_key_terms` | 规则5 | 识别并定义关键词汇和专业术语 | 高 |
| `extract_propositions` | 规则6 | 找出关键句子，提炼作者主旨 | 高 |
| `classify_book` | 规则1 | 判断书籍类型（理论性/实用性） | 中 |
| `trace_arguments` | 规则7-8 | 重构作者的论证链条 | 中 |

#### 主题阅读工具

| 工具名 | 对应步骤 | 功能说明 | 优先级 |
|--------|----------|----------|--------|
| `build_neutral_vocabulary` | 步骤2 | 建立中立词汇表，统一不同作者的术语 | 低 |
| `define_issues` | 步骤4 | 定义争议点，识别不同观点的冲突 | 低 |
| `analyze_discussion` | 步骤5 | 分析各方讨论，形成综合见解 | 低 |

#### 实现计划

**本期**：完成分层阅读的状态展示（Part 1-4）

**下期迭代**：逐步实现新工具，从高优先级开始：
1. `outline_structure` - 增强现有 `get_toc` 的结构分析能力
2. `find_key_terms` - 提取章节中的关键词和术语定义
3. `extract_propositions` - 识别作者的核心论点
