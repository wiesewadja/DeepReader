# 用户洞察系统设计

> **目标**: 让 AI 更理解用户，回答更能触动用户

## 问题定义

当前存在的三个核心问题：

1. **共鸣感不足** — AI 的回答准确但缺乏情感共鸣，像在背书
2. **个性化不够** — DeepReader.md 和记忆系统存在，但 AI 没有充分利用
3. **深度连接缺失** — 长期使用后 AI 仍像个陌生人，没有"越用越懂我"的感觉

## 解决方案概览

**核心思路**: 强化用户画像系统 + 智能更新机制 + System Prompt 增强

```
用户画像 (DeepReader.md)     对话记忆 (memory/)
        ↓                           ↓
    "我是谁"                    "发生过什么"
        ↓                           ↓
        └──────────→ System Prompt ←──────────┘
                            ↓
                      AI 更懂用户
```

## 一、用户画像结构

**文件位置**: `DeepReader/DeepReader.md`

```markdown
# 关于我

## 基础信息
称呼：[用户希望如何被称呼]
背景：[职业/年龄/专业领域]
阅读目的：[为什么读书，想获得什么]

## 阅读偏好
风格：[简洁/详尽/学术/通俗]
关注：[概念/故事/方法/观点]
笔记：[喜欢怎样的笔记格式]

## 认知特点
擅长：[熟悉的领域/思维方式]
难点：[通常在哪些方面遇到困难]
方式：[视觉型/逻辑型/案例型]

## 阅读轨迹
已读：[书名列表]
当前：[书名 + 进度]
兴趣：[想深入探索的主题]
```

**设计原则**:
- 结构化但灵活，用户可以自由填写或留空
- AI 会读取并利用这些信息来调整回答策略
- 阅读轨迹部分由系统自动维护

## 二、智能画像更新机制

### 更新触发时机

1. **对话后自动分析**（可选开关）
   - 每次对话结束后，AI 分析是否有值得记录的信息
   - 如：用户表达了新偏好、纠正了 AI 行为、透露了背景信息
   - 使用 `update_profile` 工具更新画像

2. **阅读进度同步**
   - 用户打开某本书时，自动更新"当前阅读"
   - 完成一本书时，添加到"已读书籍"

3. **用户主动编辑**
   - 用户可以随时直接编辑 `DeepReader.md`
   - 系统不会覆盖用户手动修改的内容

### 新增工具：`update_profile`

```typescript
{
  name: "update_profile",
  description: "更新用户画像的某个字段",
  parameters: {
    section: "基础信息|阅读偏好|认知特点|阅读轨迹",
    field: "具体字段名，如 '风格'、'擅长'",
    value: "新的值",
    mode: "append|replace"  // 追加还是替换
  }
}
```

**使用规则**:
- 只更新明确提及的信息，不做过度推断
- 用户手动编辑的字段优先级最高
- 每次更新在对话结束时执行，不打断对话流程

### 隐藏消息注入机制（关键设计）

**问题**：一本书只有一个长期会话，用户画像更新后需要立即生效，但不能频繁修改 System Prompt。

**解决方案**：将画像更新作为**隐藏消息**注入对话历史。

```
对话历史：
┌─────────────────────────────────────┐
│ System: [固定的 System Prompt]       │  ← 不变
├─────────────────────────────────────┤
│ User: 这本书的核心观点是什么？        │
│ Assistant: ...                       │
│ User: 以后请叫我小明                  │
│ Assistant: 好的小明，已记住。          │
│ [隐藏] User: [画像更新] 称呼=小明     │  ← 注入但不可见
├─────────────────────────────────────┤
│ User: 再解释一下                      │  ← AI 知道叫"小明"了
└─────────────────────────────────────┘
```

**实现方式**：

```typescript
// ChatMessage 类型扩展
interface ChatMessage {
  role: 'system' | 'user' | 'assistant';
  content: string;
  hidden?: boolean;  // 标记是否对用户隐藏
}

// update_profile 工具执行后
const profileUpdateMessage: ChatMessage = {
  role: 'user',
  content: `[用户画像更新]\n${section} - ${field}: ${value}`,
  hidden: true  // 界面不显示，但会发送给 LLM
};

// 注入到对话历史
messages.push(profileUpdateMessage);
```

**优点**：
1. **System Prompt 稳定** — 不需要动态重构
2. **实时生效** — 画像更新立即反映在后续对话中
3. **用户无感** — 隐藏消息不显示在界面上
4. **成本可控** — 不增加额外的 API 调用

## 三、System Prompt 增强

在 System Prompt 中添加**画像使用指南**：

```
## 用户画像使用指南

你已获得用户的画像信息（见"关于用户"部分）。请遵循以下原则：

1. **主动关联**
   - 回答问题时，结合用户背景判断深度和角度
   - 例如：用户是程序员，解释概念时可以用技术类比

2. **情感共鸣**
   - 识别用户的困惑、兴奋、挫败等情绪
   - 在回答中给予适当的情感回应，不要只是冷冰冰地输出信息

3. **个性化表达**
   - 使用用户偏好的称呼
   - 采用用户喜欢的表达风格（简洁/详尽）
   - 关注用户感兴趣的方面

4. **适度推断**
   - 根据用户的认知特点调整解释方式
   - 如果用户在某类内容上反复提问，可能是难点，需要换个角度解释

5. **记住但不刻意**
   - 自然地运用画像信息，不要说"根据您的画像..."
   - 让用户感觉到被理解，而不是被分析
```

## 四、情感共鸣场景设计

### 场景 1：洞察时刻

**触发条件**: 用户摘录、高亮、或表达对某段落的感触

**AI 行为**:
- 识别内容对用户的意义
- 给予情感回应，如"这段话确实触动人心"
- 适当延伸，但不过度解读

### 场景 2：困惑时刻

**触发条件**: 用户反复提问、表达不解、或问题中带有困惑语气

**AI 行为**:
- 先确认理解："您是在问...对吗？"
- 换个角度解释，结合用户认知特点
- 提供类比或具体案例
- 鼓励："这个问题确实不简单"

### 场景 3：成长时刻

**触发条件**: 用户完成一本书、长期阅读某主题、或表达收获

**AI 行为**:
- 回顾阅读轨迹："您从...读到..."
- 指出成长点："现在您对这个问题的理解比之前深入了"
- 给予鼓励和下一步建议

## 五、高亮标注集成

**核心价值**：用户高亮是**最强关注信号**，代表内容触动了用户。

### 按需加载机制

高亮信息在 `get_chapter` 本地读取时一并返回（从后端读取时无此数据）：

```typescript
// get_chapter 返回结构（本地读取时）
{
  content: "章节正文...",
  highlights: [  // 该章节的用户高亮
    {
      text: "高亮的文本内容",
      note: "用户批注（可选）",
      color: "yellow|green|blue|pink"  // 高亮颜色
    }
  ]
}
```

### System Prompt 引导

```
## 高亮标注处理

get_chapter 工具（本地读取时）会返回用户在该章节的高亮标注。请遵循：

1. **优先解读** - 如果用户问的内容涉及高亮段落，优先详细解读
2. **主动关联** - 回答时可以提及"您之前标注了..."
3. **情感共鸣** - 高亮代表触动，解读时要给予情感回应
4. **标注引用** - 引用高亮文本时，使用 [您标注的内容] 格式
```

### 注意事项

- 仅本地读取时有效，后端 API 不返回高亮数据
- 高亮数据来自 Obsidian 插件的阅读模式
- 无需新增工具，复用现有 `get_chapter` 即可

## 五、文件结构

```
DeepReader/
├── DeepReader.md          # 用户画像（整合配置 + 偏好 + 轨迹）
└── memory/
    ├── summary.md         # 记忆摘要
    └── entries/           # 详细记忆条目
```

**分工**:
- `DeepReader.md`：用户画像（静态配置 + 结构化偏好 + 阅读轨迹）— "我是谁"
- `memory/`：对话记忆（动态积累的具体事件）— "发生过什么"

## 八、扩展功能设计

### 8.1 阅读进度感知

**用户场景**：
- "我读到哪了？"
- "上次聊到哪？"
- "这本书还剩多少？"

**存储位置**：书籍笔记文件（AI 可直接修改）

**书籍笔记结构**（已添加 `aicreate: true`）：

```markdown
---
index_id: xxx
book_name: "西方史纲"
aicreate: true          # AI 可修改标记
status: reading
progress: 25
total_pages: 400
read_pages: "1-100"
last_read: 2026-03-10
chat_rounds: 5
tags: [历史, 西方文明]
booklists: []
created: 2026-03-01
---

# 📖 西方史纲

## 阅读进度

> 最后阅读：2026-03-10
> 当前进度：第三章 古罗马 (25%)
> 已读章节：第一章, 第二章, 第三章

## 阅读目标

> 截止日期：2026-04-10
> 每日目标：2章
> 状态：🟢 按计划进行

## 💭 阅读笔记

（用户或 AI 的阅读心得）
```

**进度推断信号**：

| 信号 | 权重 | 说明 |
|------|------|------|
| `get_chapter` 调用 | 高 | 明确获取了某章节内容 |
| 用户提问内容 | 中 | 问题涉及某章节 = 至少读到那里 |
| 用户主动标记 | 最高 | "我读完了这一章" |

**ToolContext 扩展**：

```typescript
interface ToolContext {
  // ... 现有字段
  readingProgress?: {
    currentChapter: string;
    currentChapterIndex: number;
    totalChapters: number;
    percentage: number;
    lastReadTime: string;
    daysSinceLastRead: number;

    // 阅读目标（如果有）
    goal?: {
      deadline: string;
      dailyTarget: number;
      daysRemaining: number;
      isOnTrack: boolean;
    };
  };
}
```

**System Prompt 引导**：
```
## 阅读进度感知

用户可能会问"读到哪了"、"上次聊到哪"。你可以：
1. 告知当前进度（章节、百分比）
2. 回顾上次对话的关键内容
3. 如果有阅读目标，提醒进度状态
4. 建议下一步阅读

## 更新阅读进度

当用户明确说"我读完了这一章"时，使用 update_reading_progress 工具更新进度。
```

### 8.2 关联阅读

**用户场景**：
- AI 主动提及："这个概念在您之前读的《xxx》里也提到过"
- 建立跨书籍的知识连接

**实现方式**：
- 基于用户画像中的"已读书籍"和"兴趣主题"
- AI 在回答时主动检查是否与已读书籍相关

**System Prompt 引导**：
```
## 关联阅读

当回答涉及某个概念时，检查用户画像中的"已读书籍"：
1. 如果相关概念在已读书籍中出现过，主动提及
2. 帮助用户建立跨书籍的知识连接
3. 例如："这个观点与您之前读的《xxx》中的...相呼应"
```

### 8.3 阅读目标追踪

**用户场景**：
- "我想在一个月内读完这本书"
- "帮我制定阅读计划"

**实现方式**：
- 用户画像新增"阅读目标"字段
- AI 帮助拆分计划，追踪进度

```markdown
## 阅读轨迹
已读：[书名列表]
当前：[书名 + 进度]
兴趣：[想深入探索的主题]
目标：  # 新增
  - 书名: 《xxx》
    截止: 2026-04-10
    每日: 2章
    进度: 30%
```

**System Prompt 引导**：
```
## 阅读目标追踪

如果用户设定了阅读目标：
1. 打开书籍时提示今日阅读任务
2. 进度落后时给予温和提醒
3. 完成阶段性目标时给予鼓励
4. 用户询问进度时，告知完成情况和剩余时间
```
