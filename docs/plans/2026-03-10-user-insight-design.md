# 用户洞察系统设计

> **目标**: 让 AI 更理解用户，回答更能触动用户

## 问题定义

当前存在的三个核心问题：

1. **共鸣感不足** — AI 的回答准确但缺乏情感共鸣，像在背书
2. **个性化不够** — DeepReader.md 和记忆系统存在，但 AI 没有充分利用
3. **深度连接缺失** — 长期使用后 AI 仍像个陌生人，没有"越用越懂我"的感觉

## 解决方案概览

**核心思路**: 强化用户画像系统 + 智能更新机制 + System Prompt 增强

```
用户画像 (DeepReader.md)     对话记忆 (memory/)
        ↓                           ↓
    "我是谁"                    "发生过什么"
        ↓                           ↓
        └──────────→ System Prompt ←──────────┘
                            ↓
                      AI 更懂用户
```

## 一、用户画像结构

**文件位置**: `DeepReader/DeepReader.md`

```markdown
# 关于我

## 基础信息
称呼：[用户希望如何被称呼]
背景：[职业/年龄/专业领域]
阅读目的：[为什么读书，想获得什么]

## 阅读偏好
风格：[简洁/详尽/学术/通俗]
关注：[概念/故事/方法/观点]
笔记：[喜欢怎样的笔记格式]

## 认知特点
擅长：[熟悉的领域/思维方式]
难点：[通常在哪些方面遇到困难]
方式：[视觉型/逻辑型/案例型]

## 阅读轨迹
已读：[书名列表]
当前：[书名 + 进度]
兴趣：[想深入探索的主题]
```

**设计原则**:
- 结构化但灵活，用户可以自由填写或留空
- AI 会读取并利用这些信息来调整回答策略
- 阅读轨迹部分由系统自动维护

## 二、智能画像更新机制

### 更新触发时机

1. **对话后自动分析**（可选开关）
   - 每次对话结束后，AI 分析是否有值得记录的信息
   - 如：用户表达了新偏好、纠正了 AI 行为、透露了背景信息
   - 使用 `update_profile` 工具更新画像

2. **阅读进度同步**
   - 用户打开某本书时，自动更新"当前阅读"
   - 完成一本书时，添加到"已读书籍"

3. **用户主动编辑**
   - 用户可以随时直接编辑 `DeepReader.md`
   - 系统不会覆盖用户手动修改的内容

### 新增工具：`update_profile`

```typescript
{
  name: "update_profile",
  description: "更新用户画像的某个字段",
  parameters: {
    section: "基础信息|阅读偏好|认知特点|阅读轨迹",
    field: "具体字段名，如 '风格'、'擅长'",
    value: "新的值",
    mode: "append|replace"  // 追加还是替换
  }
}
```

**使用规则**:
- 只更新明确提及的信息，不做过度推断
- 用户手动编辑的字段优先级最高
- 每次更新在对话结束时执行，不打断对话流程

### 隐藏消息注入机制（关键设计）

**问题**：一本书只有一个长期会话，用户画像更新后需要立即生效，但不能频繁修改 System Prompt。

**解决方案**：将画像更新作为**隐藏消息**注入对话历史。

```
对话历史：
┌─────────────────────────────────────┐
│ System: [固定的 System Prompt]       │  ← 不变
├─────────────────────────────────────┤
│ User: 这本书的核心观点是什么？        │
│ Assistant: ...                       │
│ User: 以后请叫我小明                  │
│ Assistant: 好的小明，已记住。          │
│ [隐藏] User: [画像更新] 称呼=小明     │  ← 注入但不可见
├─────────────────────────────────────┤
│ User: 再解释一下                      │  ← AI 知道叫"小明"了
└─────────────────────────────────────┘
```

**实现方式**：

```typescript
// ChatMessage 类型扩展
interface ChatMessage {
  role: 'system' | 'user' | 'assistant';
  content: string;
  hidden?: boolean;  // 标记是否对用户隐藏
}

// update_profile 工具执行后
const profileUpdateMessage: ChatMessage = {
  role: 'user',
  content: `[用户画像更新]\n${section} - ${field}: ${value}`,
  hidden: true  // 界面不显示，但会发送给 LLM
};

// 注入到对话历史
messages.push(profileUpdateMessage);
```

**优点**：
1. **System Prompt 稳定** — 不需要动态重构
2. **实时生效** — 画像更新立即反映在后续对话中
3. **用户无感** — 隐藏消息不显示在界面上
4. **成本可控** — 不增加额外的 API 调用

## 三、System Prompt 增强

在 System Prompt 中添加**画像使用指南**：

```
## 用户画像使用指南

你已获得用户的画像信息（见"关于用户"部分）。请遵循以下原则：

1. **主动关联**
   - 回答问题时，结合用户背景判断深度和角度
   - 例如：用户是程序员，解释概念时可以用技术类比

2. **情感共鸣**
   - 识别用户的困惑、兴奋、挫败等情绪
   - 在回答中给予适当的情感回应，不要只是冷冰冰地输出信息

3. **个性化表达**
   - 使用用户偏好的称呼
   - 采用用户喜欢的表达风格（简洁/详尽）
   - 关注用户感兴趣的方面

4. **适度推断**
   - 根据用户的认知特点调整解释方式
   - 如果用户在某类内容上反复提问，可能是难点，需要换个角度解释

5. **记住但不刻意**
   - 自然地运用画像信息，不要说"根据您的画像..."
   - 让用户感觉到被理解，而不是被分析
```

## 四、情感共鸣场景设计

### 场景 1：洞察时刻

**触发条件**: 用户摘录、高亮、或表达对某段落的感触

**AI 行为**:
- 识别内容对用户的意义
- 给予情感回应，如"这段话确实触动人心"
- 适当延伸，但不过度解读

### 场景 2：困惑时刻

**触发条件**: 用户反复提问、表达不解、或问题中带有困惑语气

**AI 行为**:
- 先确认理解："您是在问...对吗？"
- 换个角度解释，结合用户认知特点
- 提供类比或具体案例
- 鼓励："这个问题确实不简单"

### 场景 3：成长时刻

**触发条件**: 用户完成一本书、长期阅读某主题、或表达收获

**AI 行为**:
- 回顾阅读轨迹："您从...读到..."
- 指出成长点："现在您对这个问题的理解比之前深入了"
- 给予鼓励和下一步建议

## 五、文件结构

```
DeepReader/
├── DeepReader.md          # 用户画像（整合配置 + 偏好 + 轨迹）
└── memory/
    ├── summary.md         # 记忆摘要
    └── entries/           # 详细记忆条目
```

**分工**:
- `DeepReader.md`：用户画像（静态配置 + 结构化偏好 + 阅读轨迹）— "我是谁"
- `memory/`：对话记忆（动态积累的具体事件）— "发生过什么"
