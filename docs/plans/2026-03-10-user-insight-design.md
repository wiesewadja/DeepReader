# 用户洞察系统设计

> **目标**: 让 AI 更理解用户，回答更能触动用户

## 问题定义

当前存在的三个核心问题：

1. **共鸣感不足** — AI 的回答准确但缺乏情感共鸣，像在背书
2. **个性化不够** — DeepReader.md 和记忆系统存在，但 AI 没有充分利用
3. **深度连接缺失** — 长期使用后 AI 仍像个陌生人，没有"越用越懂我"的感觉

## 解决方案概览

**核心思路**: 强化用户画像系统 + 智能更新机制 + System Prompt 增强

```
用户画像 (DeepReader.md)     对话记忆 (memory/)
        ↓                           ↓
    "我是谁"                    "发生过什么"
        ↓                           ↓
        └──────────→ System Prompt ←──────────┘
                            ↓
                      AI 更懂用户
```

## 一、用户画像结构

**文件位置**: `DeepReader/DeepReader.md`

```markdown
# 关于我

## 基础信息
称呼：[用户希望如何被称呼]
背景：[职业/年龄/专业领域]
阅读目的：[为什么读书，想获得什么]

## 阅读偏好
风格：[简洁/详尽/学术/通俗]
关注：[概念/故事/方法/观点]
笔记：[喜欢怎样的笔记格式]

## 认知特点
擅长：[熟悉的领域/思维方式]
难点：[通常在哪些方面遇到困难]
方式：[视觉型/逻辑型/案例型]

## 阅读轨迹
已读：[书名列表]
当前：[书名 + 进度]
兴趣：[想深入探索的主题]
```

**设计原则**:
- 结构化但灵活，用户可以自由填写或留空
- AI 会读取并利用这些信息来调整回答策略
- 阅读轨迹部分由系统自动维护

## 二、智能画像更新机制

### 更新触发时机

1. **对话后自动分析**（可选开关）
   - 每次对话结束后，AI 分析是否有值得记录的信息
   - 如：用户表达了新偏好、纠正了 AI 行为、透露了背景信息
   - 使用 `update_profile` 工具更新画像

2. **阅读进度同步**
   - 用户打开某本书时，自动更新"当前阅读"
   - 完成一本书时，添加到"已读书籍"

3. **用户主动编辑**
   - 用户可以随时直接编辑 `DeepReader.md`
   - 系统不会覆盖用户手动修改的内容

### 新增工具：`update_profile`

```typescript
{
  name: "update_profile",
  description: "更新用户画像的某个字段",
  parameters: {
    section: "基础信息|阅读偏好|认知特点|阅读轨迹",
    field: "具体字段名，如 '风格'、'擅长'",
    value: "新的值",
    mode: "append|replace"  // 追加还是替换
  }
}
```

**使用规则**:
- 只更新明确提及的信息，不做过度推断
- 用户手动编辑的字段优先级最高
- 每次更新在对话结束时执行，不打断对话流程

### 隐藏消息注入机制（关键设计）

**问题**：一本书只有一个长期会话，用户画像更新后需要立即生效，但不能频繁修改 System Prompt。

**解决方案**：将画像更新作为**隐藏消息**注入对话历史。

```
对话历史：
┌─────────────────────────────────────┐
│ System: [固定的 System Prompt]       │  ← 不变
├─────────────────────────────────────┤
│ User: 这本书的核心观点是什么？        │
│ Assistant: ...                       │
│ User: 以后请叫我小明                  │
│ Assistant: 好的小明，已记住。          │
│ [隐藏] User: [画像更新] 称呼=小明     │  ← 注入但不可见
├─────────────────────────────────────┤
│ User: 再解释一下                      │  ← AI 知道叫"小明"了
└─────────────────────────────────────┘
```

**实现方式**：

```typescript
// ChatMessage 类型扩展
interface ChatMessage {
  role: 'system' | 'user' | 'assistant';
  content: string;
  hidden?: boolean;  // 标记是否对用户隐藏
}

// update_profile 工具执行后
const profileUpdateMessage: ChatMessage = {
  role: 'user',
  content: `[用户画像更新]\n${section} - ${field}: ${value}`,
  hidden: true  // 界面不显示，但会发送给 LLM
};

// 注入到对话历史
messages.push(profileUpdateMessage);
```

**优点**：
1. **System Prompt 稳定** — 不需要动态重构
2. **实时生效** — 画像更新立即反映在后续对话中
3. **用户无感** — 隐藏消息不显示在界面上
4. **成本可控** — 不增加额外的 API 调用

## 三、System Prompt 增强

在 System Prompt 中添加**画像使用指南**：

```
## 用户画像使用指南

你已获得用户的画像信息（见"关于用户"部分）。请遵循以下原则：

1. **主动关联**
   - 回答问题时，结合用户背景判断深度和角度
   - 例如：用户是程序员，解释概念时可以用技术类比

2. **情感共鸣**
   - 识别用户的困惑、兴奋、挫败等情绪
   - 在回答中给予适当的情感回应，不要只是冷冰冰地输出信息

3. **个性化表达**
   - 使用用户偏好的称呼
   - 采用用户喜欢的表达风格（简洁/详尽）
   - 关注用户感兴趣的方面

4. **适度推断**
   - 根据用户的认知特点调整解释方式
   - 如果用户在某类内容上反复提问，可能是难点，需要换个角度解释

5. **记住但不刻意**
   - 自然地运用画像信息，不要说"根据您的画像..."
   - 让用户感觉到被理解，而不是被分析
```

## 四、情感共鸣场景设计

### 场景 1：洞察时刻

**触发条件**: 用户摘录、高亮、或表达对某段落的感触

**AI 行为**:
- 识别内容对用户的意义
- 给予情感回应，如"这段话确实触动人心"
- 适当延伸，但不过度解读

### 场景 2：困惑时刻

**触发条件**: 用户反复提问、表达不解、或问题中带有困惑语气

**AI 行为**:
- 先确认理解："您是在问...对吗？"
- 换个角度解释，结合用户认知特点
- 提供类比或具体案例
- 鼓励："这个问题确实不简单"

### 场景 3：成长时刻

**触发条件**: 用户完成一本书、长期阅读某主题、或表达收获

**AI 行为**:
- 回顾阅读轨迹："您从...读到..."
- 指出成长点："现在您对这个问题的理解比之前深入了"
- 给予鼓励和下一步建议

## 五、高亮标注集成

**核心价值**：用户高亮是**最强关注信号**，代表内容触动了用户。

### 按需加载机制

高亮信息在 `get_chapter` 本地读取时一并返回（从后端读取时无此数据）：

```typescript
// get_chapter 返回结构（本地读取时）
{
  content: "章节正文...",
  highlights: [  // 该章节的用户高亮
    {
      text: "高亮的文本内容",
      note: "用户批注（可选）",
      color: "yellow|green|blue|pink"  // 高亮颜色
    }
  ]
}
```

### System Prompt 引导

```
## 高亮标注处理

get_chapter 工具（本地读取时）会返回用户在该章节的高亮标注。请遵循：

1. **优先解读** - 如果用户问的内容涉及高亮段落，优先详细解读
2. **主动关联** - 回答时可以提及"您之前标注了..."
3. **情感共鸣** - 高亮代表触动，解读时要给予情感回应
4. **标注引用** - 引用高亮文本时，使用 [您标注的内容] 格式
```

### 注意事项

- 仅本地读取时有效，后端 API 不返回高亮数据
- 高亮数据来自 Obsidian 插件的阅读模式
- 无需新增工具，复用现有 `get_chapter` 即可

## 七、扩展功能设计

### 8.1 阅读进度智能感知系统

**核心思路**：基于章节熟悉度计算阅读吸收度，而非简单的百分比进度。

#### 熟悉度累积模型

**触发信号与权重**：

| 信号 | 权重 | 说明 |
|------|------|------|
| `get_chapter` 调用 | +2 | 主动获取章节内容 |
| 用户提问涉及该章节 | +1 | 问了相关问题 |
| 用户高亮该章节内容 | +2 | 标注代表关注 |
| AI 回答引用该章节 | +1 | 说明讨论深入 |

#### 存储位置：书籍笔记

**Frontmatter 存储原始数据**：

```yaml
---
aicreate: true           # AI 可修改标记
index_id: xxx
book_name: "西方史纲"
status: reading

# 阅读统计
total_chapters: 10
chapter_familiarity:
  0: 5   # 第一章，熟悉度5
  1: 3   # 第二章，熟悉度3
  2: 8   # 第三章，熟悉度8（最熟悉）
  3: 1
  4: 0   # 未涉及
total_interactions: 19
last_active: 2026-03-10
created: 2026-03-01
---
```

**正文展示可视化摘要**（AI 可更新）：

```markdown
## 📊 阅读进度

> 覆盖度：60%（6/10 章节已涉及）
> 吸收度：63%（深度理解中）

### 章节熟悉度

| 章节 | 熟悉度 | 状态 |
|------|--------|------|
| 第三章 古罗马 | ████████░░ 8 | 🟥 深入 |
| 第一章 古希腊 | █████░░░░░ 5 | 🟥 深入 |
| 第六章 基督教 | ████░░░░░░ 4 | 🟧 中等 |
| 第二章 雅典民主 | ███░░░░░░░ 3 | 🟧 中等 |
| 第四章 罗马帝国 | █░░░░░░░░░ 1 | 🟨 初涉 |
| 第五、八、九章 | ░░░░░░░░░░ 0 | ⬜ 未涉及 |

### 章节热力图
🟥🟧🟥🟨⬜🟨🟧⬜⬜⬜
```

#### 进度计算公式

**两个核心指标**：

| 指标 | 计算方式 | 含义 |
|------|---------|------|
| **覆盖度** | 熟悉度 > 0 的章节数 / 总章节 | 读过多少内容 |
| **吸收度** | Σ熟悉度 / (总章节 × 基准值) | 读得多深入 |

**基准值**：假设每章提及 3 次算"基本吸收"

**示例计算**：
```
总章节：10
基准值：3
章节熟悉度：[5, 3, 8, 1, 0, 2, 4, 0, 0, 0]

覆盖度 = 7/10 = 70%（7个章节有互动）
吸收度 = (5+3+8+1+0+2+4+0+0+0) / (10×3) = 23/30 ≈ 77%
```

#### 新增工具：`update_familiarity`

```typescript
{
  name: "update_familiarity",
  description: "更新章节熟悉度",
  parameters: {
    chapterIndex: "章节索引",
    delta: "增量（默认1）",
    reason: "原因：get_chapter|user_question|highlight|ai_reference"
  }
}
```

**调用时机**：
- `get_chapter` 工具执行后自动调用（+2）
- 用户高亮时自动调用（+2）
- 对话分析后按需调用（+1）

### 8.2 关联阅读

**触发方式**：用户主动提问
- "帮我找下读过书籍中与这个主题类似的章节"
- "我之前读过类似的内容吗？"

**实现逻辑**：

1. **遍历已读书籍** — 从用户画像或书籍笔记获取已读书籍列表
2. **读取章节摘要** — 获取每个章节的 `summary` 字段
3. **AI 推理相关性** — 基于 summary 判断是否与用户问题相关
4. **读取正文回答** — 确认相关后读取章节正文

**新增工具：`search_read_books`**

```typescript
{
  name: "search_read_books",
  description: "在已读书籍中搜索与某个主题相关的章节",
  parameters: {
    query: "搜索主题/关键词",
    maxResults: "最大返回数量（默认5）"
  }
}
```

**返回值**：

```typescript
{
  results: Array<{
    bookName: string;
    chapterTitle: string;
    chapterIndex: number;
    summary: string;       // 章节摘要
    relevance: string;     // AI 判断的相关性说明
    link: string;          // wikilink
  }>;
}
```

**System Prompt 引导**：

```
## 关联阅读

当用户问"我之前读过类似的内容吗"或"帮我找相关章节"时：

1. 使用 search_read_books 工具搜索已读书籍
2. 工具会遍历所有已读书籍的章节摘要
3. 根据摘要推理相关性，返回最相关的章节
4. 如果需要详细内容，再调用 get_chapter 读取正文
5. 回答时使用 wikilink 引用相关章节
```

### 8.3 鼓励好问题

**核心价值**：对用户提出的好问题给予鼓励，增强成就感，激励更深入的思考。

**什么是"好问题"？**

| 类型 | 示例 | 特点 |
|------|------|------|
| **深度思考** | "这个观点的底层逻辑是什么？" | 追问本质 |
| **关联对比** | "这与XX理论有什么区别？" | 建立连接 |
| **批判质疑** | "作者的这个论断有依据吗？" | 独立思考 |
| **应用迁移** | "这个方法能用在其他场景吗？" | 举一反三 |

**System Prompt 引导**：

```
## 鼓励好问题

当用户提出有深度的问题时，给予适度鼓励：

1. **识别好问题** - 以下情况属于好问题：
   - 追问本质/底层逻辑
   - 建立跨概念/跨书籍的关联
   - 对观点进行批判性思考
   - 尝试迁移应用

2. **鼓励方式** - 简短自然，不要夸张
   - ✅ "这个问题问得好，触及了核心..."
   - ✅ "您抓住了关键点..."
   - ✅ "这个角度很有意思..."
   - ❌ "太棒了！您真是太聪明了！"（过于夸张）

3. **适度原则** - 不是每个问题都要鼓励
   - 普通问答直接回答即可
   - 只有真正有深度的问题才给予肯定
```
