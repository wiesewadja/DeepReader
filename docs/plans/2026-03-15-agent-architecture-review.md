# DeepReader Agent 架构优化方案

## 当前架构分析

### 1. Agent Loop 核心流程

**文件**: `frontend/src/agent/agent-loop.ts`

```
┌─────────────────────────────────────────────────────────┐
│                    Agent Loop 流程                       │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  ┌─────────┐    ┌─────────┐    ┌─────────────────────┐ │
│  │ 用户消息 │───▶│ 调用 LLM │───▶│ finishReason?       │ │
│  └─────────┘    └─────────┘    │ ├─ stop → 返回结果   │ │
│                                 │ ├─ tool_calls → 执行 │ │
│                                 │ └─ 继续循环          │ │
│                                 └──────────┬──────────┘ │
│                                            │            │
│                     ┌──────────────────────▼─────────┐  │
│                     │     并行执行工具 (Promise.all)   │  │
│                     └──────────────────────┬─────────┘  │
│                                            │            │
│                     ┌──────────────────────▼─────────┐  │
│                     │   结果注入消息历史 → 下一轮迭代   │  │
│                     └────────────────────────────────┘  │
│                                                         │
│  最大迭代: 10 轮 | Token 限制: 20000 | 超时: 60s       │
└─────────────────────────────────────────────────────────┘
```

**优点**：
- 并行工具执行效率高
- 流式响应体验好
- Token 管理自动化

**问题**：
- 迭代轮数较多时成本高
- 工具调用决策缺乏阅读层次指导

```
┌─────────────────────────────────────────────────────────┐
│                   系统提示词分层结构                      │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  Layer 1: Identity（静态）                              │

│  ├── 用户画像                                           │
```

- 阅读方法论与工具的关联不够明确
- 缺乏阅读层次的状态追踪

### 4. 拟人化状态显示

**当前实现**：
- 阅读层次徽章（🔍检视/🧐分析/📚主题）
- 工具动作映射（"搜索「xxx」"、"翻阅「章节」"）
- 进度指示

**问题**：
- 徽章只在工具执行时显示
- 缺乏阅读层次的持续展示

## 优化建议

### 优化 1：增强工具描述中的阅读层次标识

**目标**：让 LLM 更清楚地知道每个工具对应的阅读层次

**修改文件**: `frontend/src/agent/tools/*.ts`

**示例修改**（search-doc.ts）：
```typescript
description: `【检视阅读】搜索文档中与查询相关的内容。
适用场景：快速了解书籍、找到相关章节、回答"这本书讲什么"类问题。
返回：匹配的段落片段和 wiki 链接。`
```

### 优化 2：系统提示中增加工具选择指南

**目标**：指导 LLM 根据问题类型选择合适的阅读层次

**修改文件**: `frontend/src/agent/context/builder.ts`

**新增内容**（在 buildConstraints 中）：
```markdown
## 阅读层次工具选择指南

根据用户问题特征，按以下优先级选择工具：

| 问题类型 | 首选工具 | 备选工具 |
|---------|---------|---------|
| "讲什么/总结/概览" | get_toc → search_doc | - |
| "详细解释/为什么/深入" | get_chapter | outline_structure |
| "关键术语/专业词汇" | find_key_terms | get_chapter |
| "核心观点/主要论点" | extract_propositions | get_chapter |
| "比较/其他书/关联" | search_read_books | - |

**效率原则**：
1. 检视阅读能回答 → 不升级到分析阅读
2. 获得 2-3 个相关章节 → 立即回答
3. 避免重复获取同一内容
```

### 优化 3：阅读层次状态持续显示

**目标**：在 Agent 运行期间持续显示当前阅读层次

**修改文件**: `frontend/src/agent/ui/humanized-adapter.ts`

**方案**：
- 在 `HumanizedProgress` 中增加 `readingLevelState` 字段
- 记录整个会话中使用过的最高阅读层次
- 在 UI 中持续显示（而非仅在工具执行时）

### 优化 4：简化迭代流程（可选）

**目标**：减少不必要的迭代轮数

**方案 A - 降低最大迭代**：
```typescript
// 从 10 降到 5-7
const maxIterations = 7;
```

**方案 B - 智能提前终止**：
```typescript
// 如果连续 2 轮没有新信息，提前结束
if (noNewInfoCount >= 2) {
  break;
}
```

### 优化 5：增加阅读进度追踪（可选）

**目标**：让用户知道 Agent 读到哪了

**方案**：
- 在状态显示中增加"已读章节"计数
- 显示当前阅读的章节名称
- 预估剩余阅读量
