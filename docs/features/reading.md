# 阅读体验（F-17 ~ F-21）

> Obsidian 原生不擅长长文档阅读。阅读中的灵感应立即被捕获。
> "上次读到哪了"是阅读最大的摩擦。画线是深度阅读的物理动作。

---

## F-17: 分页阅读 + 章节导航

- **为什么存在**: Obsidian 原生不擅长长文档阅读。分页器模拟书的翻页体验，章节导航模拟目录，降低认知负荷。没有好的阅读体验，用户不会愿意在 DeepReader 里读书。
- **用户故事**: 作为读者，我希望在 DeepReader 里像翻书一样阅读 PDF/EPUB
- **前置条件**: 文件已索引
- **输入**: 选择书籍 + 进入阅读模式
- **输出**: 分页渲染的章节内容 + 章节导航栏
- **验收标准**:
  - [ ] 上一页/下一页快捷键工作（←/→）
  - [ ] 章节导航栏能跳转到指定章节
  - [ ] 当前页码/总页码显示
  - [ ] 翻页 < 200ms
  - [ ] 字号可调
  - [ ] 阅读位置退出后保留
- **对应测试**:
  - 单元: `tests/unit/components/page-paginator.test.ts`、`chapter-nav-keyboard.test.ts`
  - E2E: `tests/e2e/specs/reading-mode-pagination.e2e.ts`、`epub-user-flow.e2e.ts`
  - 覆盖状态: ✅ 强
- **详见**: product-manual §2.4

## F-18: 文字选择 + 工具栏

- **为什么存在**: 阅读中的灵感应立即被捕获。看到一段精彩内容，选中 → 高亮/摘录/提问，零摩擦。如果需要切换工具或记住内容再手动操作，灵感的火花就灭了。
- **用户故事**: 作为读者，我希望选中一段文字后能立即高亮、摘录或基于它提问
- **前置条件**: 阅读模式已打开
- **输入**: 鼠标选择文字
- **输出**: 悬浮工具栏（含高亮/摘录/提问按钮）
- **验收标准**:
  - [ ] 工具栏在选择后 < 300ms 出现
  - [ ] 点击外部区域自动关闭
  - [ ] 三个按钮都可点击
  - [ ] 工具栏位置不遮挡选中文本
  - [ ] 移动端长按触发
- **对应测试**: 无
- **覆盖状态**: ❌ 无
- **详见**: product-manual §2.4

## F-19: 阅读进度追踪（已移除）

> **状态**：已移除。阅读进度追踪功能已从当前版本中删除。

- **原为什么存在**: "上次读到哪了"是阅读最大的摩擦。解决后用户才愿意每次打开都继续读。没有进度恢复，每次打开都从第一页开始，等于劝退。
- **原验收标准**: 进度自动保存、重启后恢复、跨设备同步等
- **移除说明**: 阅读进度追踪功能已被移除，相关代码和存储已清理

## F-20: 高亮 + 摘录保存

- **为什么存在**: 画线是深度阅读的物理动作。高亮和摘录让"读过的痕迹"持久化，可搜索、可回看。没有它，读完就忘。
- **用户故事**: 作为读者，我希望把重要的段落高亮保存为可搜索的摘录
- **前置条件**: 阅读模式已打开
- **输入**: 选中的文字 + 触发"高亮"或"摘录"
- **输出**: 摘录文件 `书籍摘录/{书名}/摘录-{日期}.md`
- **验收标准**:
  - [ ] 高亮在阅读模式中可视
  - [ ] 摘录文件含原文 + 出处（书名/章节/页码）
  - [ ] 摘录含时间戳
  - [ ] 同一段落二次摘录不重复
  - [ ] 摘录可被 Obsidian 全局搜索
  - [ ] 失败时显示提示
- **对应测试**: 无
- **覆盖状态**: ❌ 无
- **详见**: product-manual §2.5

---

## F-21: 摘录按书籍/日期组织

- **为什么存在**: 摘录不整理就等于没摘。按书分组让用户能回溯一本书的所有洞察。这是把"摘录"升级为"知识"的关键一步。
- **用户故事**: 作为用户，我希望摘录按书名分组、按日期命名，方便回看
- **前置条件**: 已有摘录
- **输入**: 触发"整理摘录"
- **输出**: 整理后的目录结构
- **验收标准**:
  - [ ] `书籍摘录/{书名}/` 目录结构
  - [ ] 文件命名 `摘录-YYYY-MM-DD.md`
  - [ ] 同一日多次摘录合并到一个文件
  - [ ] 旧摘录不被破坏
  - [ ] 整理操作可撤销
- **对应测试**: 无
- **覆盖状态**: ❌ 无
- **详见**: product-manual §2.5
