## F-12: 工具 — search_book

- **为什么存在**: Agent 的眼睛——没有搜索工具，AI 就是瞎子，只能靠训练数据瞎说。search_book 让 Agent 从真实书籍内容中找到答案。
- **用户故事**: 作为 Agent，我需要在 LangGraph 节点中调用搜索工具获取章节片段
- **前置条件**: LangGraph 状态机已初始化；目标书已索引
- **输入**: `bookId` + 关键词数组
- **输出**: 排序后的搜索结果（章节、页码、片段、分数）
- **验收标准**:
  - [ ] 多关键词并行检索
  - [ ] 返回 Top-K（默认 5）
  - [ ] 支持按章节范围过滤
  - [ ] 100ms 内返回结果
  - [ ] 无匹配返回空数组（不抛错）
  - [ ] 错误时返回明确错误信息
- **对应测试**:
  - 单元: `tests/unit/agent/tools/local/{search-text,utils}.test.ts`
  - 覆盖状态: ✅ 强
- **详见**: product-manual §2.2.2

## F-13: 工具 — read_book_section

- **为什么存在**: Agent 的放大镜——搜索找到章节后，需要读取原文才能精确引用和分析。没有它，AI 只能说"某个章节提到了 X"，无法给出具体内容。
- **用户故事**: 作为 Agent，我需要读取指定章节的完整内容用于分析
- **前置条件**: LangGraph 状态机已初始化；目标书已索引
- **输入**: `bookId` + 章节定位（章节号 / 标题 / 页码）
- **输出**: 章节完整 Markdown 内容
- **验收标准**:
  - [ ] 按章节号/标题/页码都能定位
  - [ ] 内容包含 YAML frontmatter
  - [ ] 大章节（> 5000 字）能正确返回
  - [ ] 无效章节返回明确错误
  - [ ] 200ms 内返回结果
- **对应测试**:
  - 单元: `tests/unit/agent/tools/local/read-section.test.ts`
  - 覆盖状态: ✅ 强
- **详见**: product-manual §2.2.2

## F-14: 工具 — write_note

- **为什么存在**: 洞察不应只存在于对话里。用户和 AI 的讨论成果应该落回 Obsidian，成为持久知识——否则下次对话又要从头开始。
- **用户故事**: 作为 Agent，我需要把对话中产生的洞察写入 Vault 笔记
- **前置条件**: LangGraph 状态机已初始化；路径可写
- **输入**: 笔记内容（Markdown）+ 目标路径 + 可选 frontmatter
- **输出**: 写入成功的文件路径
- **验收标准**:
  - [ ] 写入到正确路径
  - [ ] 保留 frontmatter
  - [ ] 文件已存在时询问/追加/覆盖（按设置）
  - [ ] 路径非法时返回明确错误
  - [ ] 成功后返回的文件路径可在 Obsidian 中打开
  - [ ] 不影响 Obsidian 当前打开的文件
- **对应测试**: 无
- **覆盖状态**: ❌ 无
- **详见**: product-manual §2.3.2

## F-15: 工具 — search_read_books

- **为什么存在**: 知识在书与书之间生长。用户读得越多，跨书检索的价值越大。search_read_books 让 Agent 在所有已索引的书籍中搜索，为主题阅读和多书对比提供基础。
- **用户故事**: 作为 Agent，我需要跨多本书搜索与查询相关的内容，支持主题阅读场景
- **前置条件**: LangGraph 状态机已初始化；至少 2 本书已索引
- **输入**: `query`（搜索关键词）+ 可选 `top_k`（返回数量）
- **输出**: 跨书搜索结果列表（含书名、章节、片段）
- **验收标准**:
  - [ ] 跨多本书并行检索
  - [ ] 结果按书聚合
  - [ ] 支持按书名/作者过滤
  - [ ] 无匹配返回空结果（不抛错）
  - [ ] 错误时返回明确错误信息
- **对应测试**:
  - 单元: `tests/unit/agent/router-syntopical.test.ts`（间接）
  - 覆盖状态: ⚠️ 间接
- **详见**: product-manual §2.3.2

## F-16: 工具 — search_journal

- **为什么存在**: 用户的个人笔记也是重要的知识源。search_journal 让 Agent 在用户的 Obsidian 笔记中搜索，将个人知识与书籍内容结合，提供更精准的回答。
- **用户故事**: 作为 Agent，我需要搜索用户的个人笔记，结合书籍内容提供更精准的回答
- **前置条件**: LangGraph 状态机已初始化；笔记目录已配置
- **输入**: `query`（搜索关键词）+ 可选 `topK`（返回数量，默认 3）
- **输出**: 笔记搜索结果列表（含标题、片段、路径）
- **验收标准**:
  - [ ] 支持关键词搜索
  - [ ] 结果包含标题和片段
  - [ ] 未配置笔记目录时返回 SKIP 状态
  - [ ] topK 上限 50
  - [ ] 无匹配返回空结果（不抛错）
- **对应测试**:
  - 间接覆盖于 Agent 集成测试
  - 覆盖状态: ⚠️ 间接
- **详见**: product-manual §2.3.2

## 微信读书工具集

Agent 还集成 5 个微信读书工具（定义于 `src/agent/tools/definitions/weread-tools.ts`），用于阅读顾问模式：

| 工具 | 功能 |
|------|------|
| `weread_search` | 搜索微信读书书籍 |
| `weread_recommend` | 个性化书籍推荐 |
| `weread_readdata` | 阅读统计数据 |
| `weread_notebooks` | 笔记概览 |
| `weread_book_info` | 书籍详情查询 |

- **前置条件**: 微信读书 API Key 已配置
- **覆盖状态**: ⚠️ 间接（通过 weread 集成测试覆盖）
