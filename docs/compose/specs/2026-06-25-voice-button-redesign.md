# 语音按钮交互重设计

## [S1] 问题

当前语音输入交互 UX 不够好：
- 移动端用长按输入框触发，不够直观
- 语音按钮和发送按钮分离，占用空间
- 覆盖层是轻量浮层，不够沉浸

## [S2] 解决方案

合并语音按钮和发送按钮为一个动态按钮，点击语音按钮后输入框区域切换为语音录制界面。

**跨平台一致性**：PC 和移动端使用相同的按钮交互，移动端额外支持长按：
- 按钮位置一致（输入框右侧）
- 录制界面一致（输入框区域替换）
- 交互流程一致（点击开始/停止）

**移动端额外交互**：长按输入框也触发语音输入（与点击语音按钮功能相同）
- 长按阈值：500ms
- 上滑取消：超过 50px 取消长按
- 触发后进入与点击语音按钮相同的录制界面

**按钮状态**：
- 空文本 + 无引用 → 显示 🎤（语音按钮）
- 有文字 或 有引用 → 显示 📤（发送按钮）
- 录音中 → 显示 ⏹（停止按钮）

**语音录制界面**：
```
┌─────────────────────────────────────┐
│  消息列表（保持可见）                 │
├─────────────────────────────────────┤
│  ⏹ 停止    🔴 [波形动画]    📤 发送  │
└─────────────────────────────────────┘
```

**交互流程**：
1. 点击 🎤 → 显示语音录制界面（波形动画）
2. 点击 ⏹ → 停止录音 → ASR → LLM 重写 → 填入输入框
3. 点击 📤 → 停止录音 → ASR → LLM 重写 → 直接发送

## [S3] 架构

**改动范围**：
1. 合并语音按钮和发送按钮为一个动态按钮
2. 升级 VoiceOverlay 为输入框区域替换模式
3. 移除长按功能（不再需要 touch 事件）
4. 复用现有 PushToTalkController

**文件改动**：
| 文件 | 改动 |
|------|------|
| `chat-input.ts` | 移除 voiceButton，sendButton 动态切换图标，移除 touch 事件 |
| `chat-input.css` | 新增语音录制界面样式 |
| `voice-overlay.ts` | 重写为全屏替换模式 |
| `sidebar-view.ts` | 适配新的按钮逻辑 |

## [S4] 按钮状态机

```
空文本 + 无引用 → 显示 🎤（语音按钮）
    ↓ 点击
进入录音模式

有文字 或 有引用 → 显示 📤（发送按钮）
    ↓ 点击
发送消息

录音中 → 显示 ⏹（停止按钮）
    ↓ 点击
停止录音 → ASR → LLM 重写
```

**按钮图标切换逻辑**（在 `updateSendButtonState()` 中）：
- 无内容 + 空闲 → `Icons.mic`
- 有内容 → `Icons.send`
- 录音中 → `Icons.stop`
- 流式输出中 → `Icons.stop`（保持现有逻辑）

## [S5] 语音录制界面

点击语音按钮后，输入框区域切换为语音录制界面：

**界面元素**：
| 元素 | 位置 | 行为 |
|------|------|------|
| 停止按钮 | 左侧 | 点击停止录音，回到输入框 |
| 波形动画 | 中间 | 表示正在录音 |
| 发送按钮 | 右侧 | 点击停止录音 + 直接发送 |

**状态流转**：
```
点击 🎤 → 录音界面（波形动画）→ 点击 ⏹ → ASR → LLM 重写 → 填入输入框
                        ↓
                点击 📤 → ASR → LLM 重写 → 直接发送
```

## [S6] 配置与依赖

**配置来源**：
| 配置 | 来源 | 用途 |
|------|------|------|
| ASR apiKey/baseUrl | `resolveRoleConfig("tts")` | MiMo ASR 调用 |
| LLM apiKey/baseUrl | `resolveRoleConfig("chat")` | VoiceRewriter 调用 |
| 书籍上下文 | `BookManager` | 重写时提供书名/摘要 |

**复用模块**：
- `PushToTalkController`：状态机 + ASR + LLM 重写
- `AudioRecorder`：录音
- `ASRClient`：语音识别
- `VoiceRewriter`：口语→书面语
