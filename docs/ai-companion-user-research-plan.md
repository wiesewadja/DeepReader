# DeepReader「AI 伴读体验」用户研究计划
### 面向知识工作者 · 混合方法(Mixed Methods)

> UX Researcher: 探真真 ｜ 日期: 2026-07-06 ｜ 状态: 待评审启动
> 适用范围: DeepReader 插件(Obsidian,代号「奚童」)AI 伴读模块

---

## 0. 研究背景与产品定位

DeepReader 是运行在 Obsidian 内的 AI 伴读插件,核心由 **LangGraph 四层认知引擎 + FrontendAgent** 驱动,辅以 PDF/EPUB 索引、微信读书同步、以及**渐进式用户画像 + 长期记忆(MEMORY.md 渐进理解用户)**。

本次研究聚焦 **AI 伴读体验**,目标人群为 **知识工作者**。研究中必须覆盖的关键特性:

- **四层认知引擎**:分层次的理解 / 推理 / 记忆能力
- **FrontendAgent.chat() → runGraphEngine() → stream()**:对话式伴读主链路
- **渐进式用户画像 + 长期记忆**:隐私 / 信任高度敏感
- **阅读模式服务、可视化(Excalidraw 图表)、TTS/ASR 语音**

---

## 1. 研究目标与核心问题

### 1.1 总体目标
建立对知识工作者在「AI 辅助阅读与知识内化」场景下的真实需求、行为模式、痛点与信任边界的科学理解,为 AI 伴读的下一代设计提供证据基础(而非假设基础)。

### 1.2 核心研究问题(RQ)
- **RQ1(心智模型)**:知识工作者如何理解「AI 伴读」?期望 AI 在阅读哪个环节介入(前 / 中 / 后)?主动 vs. 被动的偏好?
- **RQ2(价值感知)**:四层认知引擎带来的「分层深度理解」,用户是否**实际感知**到?相比通用聊天机器人,差异化价值是否成立?
- **RQ3(信任与隐私)**:渐进式用户画像 + 长期记忆被接受吗?哪些数据边界会触发不信任 / 抵触?
- **RQ4(工作流嵌入)**:AI 伴读如何嵌入 Obsidian 既有知识管理流(笔记 / 双链 / 图谱)?摩擦点在哪里?
- **RQ5(可用性 & 无障碍)**:当前已部署版本在 PC / Mobile 双端的任务完成度、效率与无障碍可达性如何?

### 1.3 待验证假设
- **H1**:用户更看重「帮我真正理解并连接知识」,而非「摘要 / 速读」。
- **H2**:四层引擎的「深度」在默认交互下用户**无感**,需显性化才被感知。
- **H3**:长期记忆功能因隐私顾虑,导致高价值用户放弃使用(流失风险点)。
- **H4**:移动端因翻页 / 选区兼容问题,伴读任务完成率显著低于 PC 端。

## 2. 方法论:为什么选混合方法

单一方法无法同时回答「为什么」(定性)与「多少人 / 多大」(定量)。采用 **解释性序列混合设计(Explanatory Sequential)**:

1. 先用**定性(深访)**生成假设与用户语言;
2. 再用**定量(问卷)**验证其普遍性与优先级;
3. 最后用**可用性测试**检验当前版本的可达性与痛点密度。

三角验证可显著降低单一方法的偏差(如仅访谈导致的过度概括、仅问卷导致的表面化)。

## 3. 四阶段详细方案

### 阶段一 · 生成式定性研究(深度访谈)
- **目标**:回答 RQ1 / RQ2 / RQ3 / RQ4,建立心智模型与痛点假设。
- **方法**:1 对 1 半结构化访谈 + 情境访谈(请用户展示自己真实阅读 / 笔记流)。
- **样本**:**12 人**(知识工作者;6 名现 DeepReader 用户 + 6 名竞品 / 无 AI 伴读用户,用于对照)。
- **时长**:60 分钟 / 人,录屏 + 录音(需同意)。
- **产出**:原始编码、初步 Persona、痛点假设清单。

**访谈提纲大纲(节选)**:
1. 你平时读什么、为何读?阅读后如何沉淀?(现有工作流)
2. 你用过哪些 AI 阅读 / 笔记工具?满意 / 不满在哪?
3. 设想 AI 在你阅读时「陪你」:你希望它做什么、不做什么?
4. 展示 DeepReader 伴读 demo:哪些让你觉得「懂我」?哪些像普通机器人?
5. 如果 AI 逐渐「记住你是谁、你怎么思考」,你的感受?边界在哪?

### 阶段二 · 定量验证(问卷)
- **目标**:验证阶段一假设的普遍性,量化优先级(RQ1–RQ4)。
- **样本量论证**:总体比例未知,取最保守 p=0.5、95% 置信、±7% 误差 → n≈196。计划回收 **n=200**(含 ~10% 无效样本冗余)。
- **方法**:结构化在线问卷,含成熟量表以保证信效度:
  - **UMUX-LITE**(易用性 / 可用性感知)
  - **TTF**(任务-技术适配)+ **信任量表**(含隐私关切子维度)
  - **功能优先级**:MaxDiff / 卡片排序(让用户在 8–10 项伴读能力中排序)
  - 人口与行为变量(角色、阅读量、Obsidian 熟练度、平台)
- **投放**:知识工作者社群、Obsidian 中 / 英文论坛、行业微信群(多渠防偏倚)。
- **产出**:描述统计、分组差异、优先级排序、假设验证结论。

### 阶段三 · 可用性测试(当前部署版本)
- **目标**:回答 RQ5,定位当前版本可用性与无障碍问题。
- **样本**:**8 人**(PC 5 + Mobile 3;含至少 1 名无障碍需求用户,如阅读障碍 / 运动障碍辅助技术使用者——满足包容研究要求)。
- **环境**:**Obsidian test-vault 内运行**(非浏览器;按 AGENTS.md 约束禁用浏览器 MCP)。移动端用真机。
- **任务场景**(基于真实伴读流):
  - **T1**:向 AI 提问本章核心论点,并让它关联你过往笔记(验证四层引擎 + 长期记忆)
  - **T2**:让 AI 将一段复杂内容生成可视化图表(Excalidraw)
  - **T3(移动端)**:在手机上翻页并选中文本唤起伴读工具条
- **指标**:任务完成率、时长、错误数、SUS、情感评分;移动端对比 PC 完成率(验证 H4)。
- **产出**:可用性问题清单(严重度分级)、SUS 分数、无障碍合规差距。

### 阶段四 · 综合分析与三角验证
- 主题分析(阶段一)+ 统计分析(阶段二)+ 可用性指标(阶段三)汇入 **三角验证矩阵**。
- 优先级排序:**影响力(用户价值 / 频率)× 实施成本** → 路线图建议。
- **产出**:Persona 终稿、用户旅程地图(含情绪曲线)、洞察报告、设计建议。

## 4. 参与者标准与招募

### 纳入标准
- 18–55 岁,自认「知识工作者」(研究 / 产品 / 咨询 / 学术 / 内容等),每周主动阅读 ≥ 3 小时。
- 至少使用过一种笔记 / 知识管理工具;Obsidian 用户优先但不限。
- 覆盖 PC 与 Mobile 双端使用者。

### 排除
- DeepReader 核心开发 / 密切接触者(避免内部视角偏差)。
- 过去 3 个月参与过同类研究。

### 多样性与包容(强制)
- 性别均衡(±15%);年龄跨 20s–50s;至少 1 名无障碍需求用户;城乡 / 行业多元。

### 招募与激励
- 渠道:社群 + 论坛 + 转介;访谈 ¥200 / 人,问卷抽奖,可用性 ¥150 / 人。
- 防偏倚:不只在 Obsidian 重度用户群投放,避免「幸存者偏差」。

## 7. 数据伦理与隐私(重点)
- **知情同意**:明确告知 AI 伴读会构建长期记忆 / 用户画像,数据用途与留存。
- **数据安全**:访谈录音本地加密,问卷匿名化,符合个保法 / GDPR 精神。
- **无障碍合规**:阶段三遵循 WCAG 2.1 AA 任务设计。
- **客观呈现**:避免确认偏误,负面结论同等呈现。
