# LLM 树搜索功能指南

## 概述

LLM 树搜索（`llm_tree_search`）是 DeepPDF Agent 的高级检索工具，通过结合混合检索和 LLM 推理，实现跨章节的深度内容理解。与传统基于关键词或向量相似度的检索不同，LLM 树搜索能够理解文档的逻辑结构，适合需要综合分析的复杂查询。

### 核心特性

- **两阶段检索架构**：先粗筛后精排，平衡性能和质量
- **缓存机制**：相同查询直接返回缓存结果，减少 LLM 调用
- **降级策略**：LLM 失败时自动回退到混合检索
- **智能模型选择**：根据候选节点数量自动选择轻量或推理模型

## 使用场景

### 适合使用 `llm_tree_search` 的场景

| 场景类型 | 示例查询 | 推荐理由 |
|---------|---------|---------|
| 跨章节推理 | "书中关于财富的论述分布在哪些章节？" | 需要理解多个章节的关联关系 |
| 模糊问题 | "作者如何看待技术对人类的影响？" | 关键词不明显，需要语义理解 |
| 逻辑分析 | "论证体系的核心观点是什么？" | 需要理解文档的整体逻辑结构 |
| 综合总结 | "总结关于教育的三个主要观点" | 需要从多个章节提取和综合信息 |

### 适合使用 `hybrid_search` 的场景

| 场景类型 | 示例查询 | 推荐理由 |
|---------|---------|---------|
| 简单事实查询 | "量子力学是什么时候提出的？" | 关键词明确，快速检索即可 |
| 精确定位 | "第 5 章讲了什么？" | 直接定位到具体章节 |
| 名词解释 | "什么是熵增定律？" | 定义类内容，向量检索效果好 |
| 引用查找 | "书中提到的 Turing 测试在哪页？" | 需要具体位置而非综合分析 |

## 架构设计

### 两阶段检索流程

```
┌─────────────────────────────────────────────────────────────────┐
│                         用户查询                                  │
└────────────────────────────┬────────────────────────────────────┘
                             │
                             ▼
┌─────────────────────────────────────────────────────────────────┐
│  阶段 1：粗筛（HybridSearchTool，Top-20）                          │
│  ───────────────────────────────────────────────────────────   │
│  1. 标题匹配：在章节标题中查找相关内容                            │
│  2. BM25 检索：全文关键词加权匹配                                 │
│  3. 向量检索：语义相似度匹配                                      │
│  4. 混合评分：综合多种排序方式返回 Top-20 候选节点                 │
└────────────────────────────┬────────────────────────────────────┘
                             │
                             ▼
┌─────────────────────────────────────────────────────────────────┐
│  阶段 2：精排（LLM 推理）                                          │
│  ───────────────────────────────────────────────────────────   │
│  1. 构建候选子树：从 Top-20 节点提取标题、摘要等信息               │
│  2. 模型选择：根据节点数量选择轻量/推理模型                        │
│  3. 构建 Prompt：使用 PromptBuilder 生成结构化指令                │
│  4. LLM 调用：让 LLM 评估节点相关性并排序                          │
│  5. 结果提取：解析 LLM 返回的 JSON，获取 Top-K 节点                │
└────────────────────────────┬────────────────────────────────────┘
                             │
                             ▼
┌─────────────────────────────────────────────────────────────────┐
│  结果生成：为每个节点生成 Obsidian 引用链接                         │
└─────────────────────────────────────────────────────────────────┘
```

### 缓存机制

- **缓存键**：`MD5(query)` - 使用查询的哈希值作为缓存键
- **缓存内容**：完整的结果 JSON（包含 obsidian_link、page、text 等）
- **缓存生存时间**：默认 300 秒（可在初始化时配置）
- **缓存优势**：相同查询直接返回，无需重复 LLM 调用

### 降级策略

在以下情况下，工具会自动降级到 `hybrid_search` 的原始结果：

1. **LLM 调用失败**：网络错误、API 限流等
2. **JSON 解析失败**：LLM 返回格式不符合预期
3. **空结果**：LLM 未返回任何有效节点

## 启用方法

### 后端 API 调用

在 Agent 查询请求中设置 `enable_llm_tree_search=true`：

```python
import requests

response = requests.post(
    "http://localhost:6088/api/agent/query",
    json={
        "index_id": "your_index_id",
        "query": "书中关于财富的论述分布在哪些章节？",
        "enable_llm_tree_search": True  # 启用 LLM 树搜索
    }
)

result = response.json()
print(result["answer"])
```

### 代码集成

在自定义代码中使用：

```python
from deeppdf.agent.core import DeepPDFAgent

agent = DeepPDFAgent(
    index_id="your_index_id",
    storage_dir="/path/to/storage",
    tree_structure=tree_structure,
    index_metadata=index_metadata,
    enable_llm_tree_search=True,  # 启用 LLM 树搜索
    llm_provider="deepseek"
)

# 执行查询
answer = agent.run("你的问题")
```

## 返回格式

`llm_tree_search` 返回与 `hybrid_search` 一致的 JSON 格式，便于统一处理：

```json
[
    {
        "node_id": "node_42",
        "obsidian_link": "[[book.md#^page-15]]",
        "page": 15,
        "anchor": "^page-15",
        "text": "财富的本质是..."
    },
    {
        "node_id": "node_87",
        "obsidian_link": "[[book.md#^page-32]]",
        "page": 32,
        "anchor": "^page-32",
        "text": "关于财富分配的观点..."
    }
]
```

**字段说明**：

- `node_id`：节点唯一标识符
- `obsidian_link`：Obsidian wiki 链接，可直接在笔记中使用
- `page`：页码
- `anchor`：锚点，用于精确定位
- `text`：节点内容摘要（前 500 字符）

## 性能考虑

### LLM 调用成本

- **轻量模型**（节点数 ≤ 10）：适合简单查询，成本较低
- **推理模型**（节点数 > 10）：适合复杂分析，成本较高

### 缓存优化

- 缓存生存时间默认 300 秒，可根据需求调整
- 对于重复查询，缓存可显著减少 LLM 调用
- 缓存键基于查询的 MD5 哈希，避免重复计算

### 推荐实践

1. **简单查询优先使用 `hybrid_search`**：快速且低成本
2. **复杂分析启用 `llm_tree_search`**：深度理解，但注意成本
3. **监控日志**：关注 `[FALLBACK]` 标识，及时发现问题
4. **合理设置缓存时间**：平衡性能和数据新鲜度

## 常见问题

### Q: 如何判断应该使用哪个工具？

**A:** 参考以下决策树：

```
是否需要跨章节推理或理解文档逻辑？
├─ 是 → 使用 llm_tree_search
└─ 否 → 是否是简单事实查询？
    ├─ 是 → 使用 hybrid_search
    └─ 否 → 根据查询复杂度选择
```

### Q: LLM 树搜索失败时会怎样？

**A:** 工具会自动降级到 `hybrid_search` 的结果，并记录 `[LLM_TREE_SEARCH][FALLBACK]` 日志。用户仍能获得检索结果，只是可能不如 LLM 精排准确。

### Q: 缓存会占用多少内存？

**A:** 每个缓存项约 1-5 KB（取决于结果大小）。默认缓存时间 300 秒，对于中等流量应用，内存占用可忽略不计。

### Q: 可以自定义 LLM 模型吗？

**A:** 目前工具根据节点数量自动选择轻量或推理模型。未来版本可能支持自定义模型配置。
