## 性能瓶颈分析

### 已识别的热点

1. **LLM 调用**（~200ms）
   - 主要瓶颈：网络延迟 + 模型推理
   - 优化空间：缓存、异步处理

2. **插件加载**（~210ms）
   - 主要开销：模块初始化、索引加载
   - 优化空间：懒加载、代码分割

3. **内存占用**（358MB RSS）
   - 主要来源：Obsidian 框架 + 插件 + 索引
   - 优化空间：内存池、垃圾回收优化

## 优化建议

### 短期优化（1-2 周）

1. **LLM 响应优化**
   - 实现响应缓存（相同查询复用结果）
   - 添加流式响应（减少首字节时间）

2. **插件加载优化**
   - 延迟加载非核心模块
   - 预加载常用索引数据

### 中期优化（1-2 月）

1. **内存优化**
   - 实现对象池（减少 GC 压力）
   - 优化大数据结构（压缩存储）

2. **搜索优化**
   - 实现搜索结果缓存
   - 优化 BM25/向量搜索算法

### 长期优化（3-6 月）

1. **架构优化**
   - Web Worker 并行处理
   - 增量索引更新

2. **存储优化**
   - 压缩索引数据
   - 实现分层存储
