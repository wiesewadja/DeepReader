# ADR-002: 本地优先，纯前端，无后端

## 状态
Accepted

## 日期
2026-03（项目创始）

## 背景

阅读助手需要存储用户的书籍索引、搜索数据、对话历史。需要决定架构是本地还是云端。

## 决策

所有数据存储在用户的 Obsidian Vault 中（本地文件系统），不部署后端服务。LLM API 调用是唯一的外部依赖。

## 替代方案

### 云端后端 + 本地客户端
- 优点：可以提供更强大的搜索（Elasticsearch）、更快的向量化、跨设备同步
- 缺点：需要运维服务器、用户数据离开本地、隐私风险、需要付费
- 放弃原因：Obsidian 用户的核心理念是数据本地化。云端方案与用户期望冲突

### 混合架构（本地为主 + 云端可选）
- 优点：兼顾本地隐私和云端能力
- 缺点：架构复杂度翻倍、需要维护两套代码路径
- 放弃原因：团队规模（1人）无法维护双架构

## 后果
- 搜索能力受限于本地计算（BM25 + 轻量向量，不能用 Elasticsearch）
- 索引大书时可能影响 Obsidian 性能（用 PI 子进程隔离）
- 跨设备同步依赖用户自建的 Vault 同步方案（iCloud/OneDrive/Git）
- 隐私是卖点：用户数据不离开 Vault
