# ADR-001: 四层阅读法作为 Agent 认知架构

## 状态
Accepted

## 日期
2026-03（项目创始）

## 背景

AI 阅读助手需要决定如何组织认知过程。通用 RAG 方案（用户提问 → 检索 → 回答）把所有问题同等对待，但阅读天然有不同深度：
- "这本书讲什么" → 快速浏览目录
- "第三章的核心论点是什么" → 深入原文分析
- "A 和 B 对 X 的观点有何不同" → 跨书对比

## 决策

采用艾德勒《如何阅读一本书》的四层阅读法作为 Agent 状态机架构：
- depth=0：闲聊（无书籍上下文）
- depth=1：检视阅读（目录导航、结构概览）
- depth=2：分析阅读（ReAct 循环，深入原文）
- depth=3：主题阅读（多书对比）

每层有专属的工具集、提示策略和模型配置。

## 替代方案

### 通用 RAG 对话链
- 优点：实现简单，一个 prompt 打天下
- 缺点：无法区分用户意图的深度，浅层问题浪费 token，深层问题搜索不足
- 放弃原因：阅读认知过程天然分层，通用方案无法匹配

### 固定工作流（无状态机）
- 优点：更简单，线性流程
- 缺点：无法根据中间结果动态调整策略（如提早停止、切换搜索范围）
- 放弃原因：阅读是非线性的认知过程

## 后果
- Router 是关键组件——路由错误意味着整条路径错误
- 需要为每层维护独立的提示和工具配置
- 主题阅读（depth=3）需要跨书搜索基础设施
